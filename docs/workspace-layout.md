# Рабочее пространство и вспомогательные каталоги

[Карта проекта](../README.md) · [Документация](README.md)

## Правило размещения

Основной проект — `C:\App\Bee_search`. Новые вспомогательные каталоги Bee Search
вне checkout создаются внутри `C:\App\Bee_search_support`, в подходящем
подкаталоге по назначению. Внутрирепозиторные `tools/`, `docs/`, `build/` остаются
на своих местах. Не создавать новые sibling-каталоги `C:\App\Bee_search_*`
ради временной работы; необходимое исключение предварительно согласовать.

Существующие Git checkout/worktree и каталоги с путевыми зависимостями остаются
на месте. Привязка к GitHub сама по себе не определяет возможность переноса:
нужны также проверки локального Git metadata, скриптов и ссылок.

## Новые материалы

Создавайте только реально нужный подкаталог, например `worktrees/`, `releases/`,
`backups/`, `evidence/`, `research/` или `inputs/` внутри support.
Новые Git worktree создавайте штатными Git-командами сразу по выбранному пути.
Индексы не должны перечислять generated files поштучно.

## Проверка перед простым переносом существующей папки

1. Установить назначение, владельца и наличие Git metadata; не читать backup/raw payload без необходимости.
2. Проверить скрипты, конфигурацию, shortcuts и ссылки, использующие старый путь.
3. Выбрать один конечный путь внутри support; проверить отсутствие конфликта.
4. Перенести только согласованный каталог, сверить состав/байты и обновить действующие ссылки.
5. Исторические отчёты с прежним путём сохранить; записать соответствие старого и нового мест.

Пока ни один существующий каталог не признан ненужным и ни один не перенесён.
Массовая чистка или миграция рабочего пространства этой картой не разрешается.
