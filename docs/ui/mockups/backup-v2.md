# Резервное копирование — макет v2 (storyboard)

**Статус:** mockup v2 **утверждён владельцем** (mockup-first gate CLOSED / APPROVED). Это текущий
утверждённый визуальный эталон для production-слайса резервного копирования. Production-реализация ещё
**не начата**.

**Визуальный эталон:** `docs/ui/mockups/backup-v2.png` — один storyboard, пять состояний одного экрана.

**Визуальная основа:** ранее утверждённый владельцем storyboard
`C:\App\Bee_search_ui_input\Макет интерфейса резервного копирования.png` (по нему делался S2). Это
**эволюция** того же экрана, а не новый дизайн: сохранены визуальный язык, карточная композиция,
иерархия, стиль Android/Bee Search, положение и вес основной кнопки, модель Ready → Working →
Success/Error и цветовая семантика (зелёный успех, красный ошибка).

При расхождении PNG и этого файла: PNG определяет композицию, этот файл — семантику и поведение.
PNG утверждённой версии больше не изменяется.

Связанные принятые документы (не пересматриваются): `docs/backup-operation-design.md` (инвариант
одного захвата), `docs/user-workflows.md` §45–§47, решения D099, D100, D101.

## 1. Одна пользовательская операция

Для пользователя резервное копирование — **одна операция и одна основная кнопка**:

```
Создать резервную копию
```

Внутри одной операции приложение сохраняет данные исследований и относящиеся к ним фото и видео и
проверяет их. Отдельной кнопки `Сохранить фото и видео` нет: граница «данные / медиа» — внутренняя и
пользователю не показывается.

## 2. Панели storyboard

| № | Панель | Что показывает |
|---|---|---|
| 1 | Готово — блок свёрнут | основной экран в обычном состоянии |
| 2 | Готово — блок раскрыт | тот же экран с раскрытым перечнем состава копии |
| 3 | Создание резервной копии | выполнение операции, неопределённый индикатор |
| 4 | Успех | копия создана, результат проверки медиа |
| 5 | Ошибка сохранения фото и видео | копия не создана, повторная попытка |

Панель «нет фото и видео» отдельно не рисуется: это то же состояние успеха, отличающееся только
текстом (см. §5.6). Экран `Настройки` не рисуется — точка входа «Настройки → Резервное копирование»
уже реализована и не меняется.

## 3. Что убрано из исходного макета

| Убрано | Почему |
|---|---|
| проценты (`45 %`) и progress bar с процентами | длительность операции не измеряется; процент был бы выдуманным (решение S2: только неопределённый прогресс) |
| кнопка `Отмена` | отдельная архитектура отмены не вводится; поведение при Back/background для длинных операций — предмет S5 |
| `METADATA_ONLY`, `FULL`, `LOCAL_VERIFIED`, `NO_MEDIA_EVIDENCE` | внутренние профили копии |
| SHA, snapshot UUID, repository UUID, имя файла копии, технический размер | внутренние детали формата и хранения |
| `Фото и видео пока в эту копию не входят` (и вариант в тексте успеха) | в конечной семантике фото и видео входят в копию |
| строки `Тип`, `Размер`, `Файл` в блоке последней копии | технические данные, пользователю не нужны |
| иконка справки `?` в app bar | действие справки не входит в текущий слайс; интерактивный элемент без реализованного поведения не оставляется |
| список внутренних этапов операции | внутренние шаги pipeline |
| панели 6–8 исходного storyboard (детали копии, список копий, действия с копией) | вне текущего слайса: нет истории копий, переименования, удаления, restore, share, PC/offload UI |

## 4. Готово (панели 1–2)

### 4.1. Возврат и доступ

- Возврат — стандартная кнопка Back (`←`) в app bar; возвращает в `Настройки`. Она не является
  раскрытием списка и не изображается как chevron.
- Иконки справки в app bar нет: действие справки не входит в этот слайс.
- `Доступно` с зелёной галочкой в круге; состояния доступа остаются принятыми в S1/S2
  (`Разрешить доступ`, `✓ Доступно`, `Восстановить доступ`, понятные ошибки доступа, `Проверить снова`).
- Тексты и переходы доступа этим макетом не пересматриваются.

### 4.2. Путь к папке — информационная строка

- Подпись: `Резервные копии Bee Search сохраняются в:`
- Значение: `Загрузки/BeeSearch/<variant>/Backup` (в макете показан `Dev`).
- Строка только сообщает пользователю, где лежат резервные копии. В текущем слайсе она **не является
  кнопкой**: у неё нет chevron и других признаков перехода, она не открывает файловый менеджер и не
  открывает папку.
- Путь остаётся визуально выделенным (плашка и акцентный цвет) как значение, а не как действие.
- Этот макет **не определяет** действие открытия папки. Если такое действие когда-нибудь
  понадобится, оно потребует отдельного решения владельца и отдельного слайса; в текущем
  production-слайсе визуально активный элемент без реализованного поведения не допускается.

### 4.3. Блок «Что сохраняется в резервной копии»

- Свёрнуто: заголовок `Что сохраняется в резервной копии`, подзаголовок `Данные исследований,
  настройки, фото и видео`, affordance раскрытия (chevron). Подзаголовок может занимать две строки;
  карточка растёт по фактической высоте текста.
- Раскрыто — пользовательский перечень (подзаголовок сохраняется):

```
• Территории и ареалы
• Точки наблюдения и погода
• Наблюдения за пчёлами и циклы полётов
• Дупла
• Колоды
• Настройки приложения
• Фото и видео, относящиеся к этим данным
```

- Ареал не изображается как разновидность физического объекта.
- Запрещены: имена Room-сущностей, имена таблиц, `JSONL`, `manifest`, `profile`, `schema` и другие
  внутренние технические названия.
- Блок остаётся читаемым при увеличенном системном fontScale; вертикального текста и ломаных строк нет.

### 4.4. Граница обещания — постоянно видимая строка

В обычном состоянии Ready **всегда** видна спокойная строка:

```
Копия хранится на этом телефоне. Передача на компьютер выполняется отдельно.
```

Она не прячется внутрь раскрытого перечня: это долговременная продуктовая граница, а не временная
backend-деталь. Локальная копия не является защитой от потери или поломки телефона.

Запрещённые формулировки: `все данные защищены`, `фото защищены`, `безопасно сохранено`,
`облачная копия` и любые другие обещания внешней сохранности.

### 4.5. Последняя резервная копия

- `Последняя резервная копия` + пользовательские дата и время.
- Без UUID, SHA, имени файла копии и технического размера.
- Источник истины в production — содержимое резервного хранилища (repository discovery); отдельное
  сохранённое «последнее состояние» не создаётся.

### 4.6. Постоянного media-счётчика нет

В обычном Ready **не показывается** ни `Фото и видео / 4 файла в резервном хранилище`, ни любой другой
постоянный счётчик. Причина: такой счётчик связывает UI с будущей политикой проверки больших
хранилищ (S5) и может быть прочитан как постоянно подтверждённая целостность. При обычном открытии
экрана полное чтение и хеширование всех медиа не требуется.

После **только что** успешно завершённой операции допускается `Проверено: N из N файлов` — это
результат конкретной операции, а не долговременное утверждение о хранилище, и он не сохраняется как
постоянное состояние экрана.

## 5. Точные тексты

### 5.1. Готово

- заголовок экрана: `Резервное копирование`, кнопка Back (`←`) — возврат в `Настройки`; иконки справки нет
- доступ: `Доступно`
- подпись пути: `Резервные копии Bee Search сохраняются в:`
- путь: `Загрузки/BeeSearch/<variant>/Backup` — информационная строка, без признаков перехода
- блок: `Что сохраняется в резервной копии` / `Данные исследований, настройки, фото и видео`
- граница: `Копия хранится на этом телефоне. Передача на компьютер выполняется отдельно.`
- последняя копия: `Последняя резервная копия` + дата и время; при отсутствии копий —
  `Резервных копий пока нет`; при непроверяемой копии — существующее предупреждение
  `Не удалось проверить одну из сохранённых копий.`
- кнопка: `Создать резервную копию`

### 5.2. Создание

```
Создание резервной копии…
Данные, фото и видео сохраняются и проверяются.
```

Неопределённый индикатор. Кнопка остаётся в той же композиционной области и недоступна. Не
показываются: проценты, байты, этапы внутреннего pipeline, SHA, имена файлов, внутренние профили,
кнопка `Отмена`. Продуктовая семантика Back/background для длинных операций здесь **не фиксируется**
(решается в S5).

### 5.3. Успех

```
Резервная копия создана
Данные исследований и относящиеся к ним фото и видео сохранены в резервном хранилище на этом телефоне.
```

Если в зафиксированном состоянии были фото и видео — дополнительно результат операции:

```
Проверено: 4 из 4 файлов
```

и обновлённая `Последняя резервная копия` с новой датой и временем.

Успех показывается **только** если все фото и видео, требуемые неизменяемым захватом этой операции,
находятся в резервном хранилище и проверены, а копия этого же захвата успешно опубликована.
Пользовательского partial success нет.

### 5.4. Ошибка сохранения фото и видео

```
Резервная копия не создана
Не удалось сохранить 1 из 4 файлов фото или видео.
Уже сохранённые файлы останутся в резервном хранилище. Повторите попытку.
```

Основное действие: `Повторить`.

Правила:

- копия этой операции не публикуется; `Резервная копия создана` не показывается;
- состояния «частичная резервная копия» нет;
- уже корректно принятые файлы остаются и при следующей операции переиспользуются;
- не используется формулировка `Данные исследований не изменены`;
- backend-результаты (`ALREADY_PRESENT` и подобные) пользователю не показываются.

### 5.5. Раскрытый блок

Список из §4.3 + граница обещания (§4.4) остаётся видимой; кнопка не сдвигается.

### 5.6. Состояние без фото и видео

Отдельная панель и отдельная строка не добавляются: `Проверено: 0 из 0` не показывается, и строка
«нет фото и видео» оценена как не добавляющая полезной информации. В этом случае текст успеха
описывает только данные исследований и настройки:

```
Резервная копия создана
Данные исследований и настройки сохранены в резервном хранилище на этом телефоне.
```

## 6. Состояния и переходы

| Состояние | Строка результата | Кнопка |
|---|---|---|
| Готово, свёрнуто / раскрыто | — | `Создать резервную копию` |
| Создание | `Создание резервной копии…` + пояснение | та же, недоступна |
| Успех | `Резервная копия создана` + текст + `Проверено: N из N файлов` | `Создать резервную копию` |
| Ошибка фото и видео | `Резервная копия не создана` + объяснение | `Повторить` |
| Доступ не выдан / потерян | существующие состояния S1 | `Разрешить доступ` / `Восстановить доступ` |
| Копий нет | `Резервных копий пока нет` | `Создать резервную копию` |

## 7. Композиция, fontScale и Samsung

- Композиция проверена на устойчивость при реальном системном fontScale (для проекта около 1.7):
  длинный путь переносится внутри своей карточки, заголовок раскрываемого блока и подзаголовок
  `Данные исследований, настройки, фото и видео` могут занимать по две строки (карточка растёт по
  фактической высоте текста и не перекрывает соседние строки), перечень переносится построчно,
  сообщение об ошибке переносится внутри своей карточки.
- Не допускаются: вертикальный текст, кнопка в несколько узких нечитаемых строк, наложение текста,
  обрезка критической информации, чрезмерная плотность.
- Основная кнопка сохраняет одну и ту же позицию во всех состояниях и остаётся доступной без ручной
  прокрутки; раскрытый перечень — часть одного scroll-контура.
- `backup-v2.png` нарисован с запасом по размеру текста; фактические размеры на устройстве определяет
  Android (адаптивность, системные отступы, доступность). Отдельный PNG для fontScale не требуется.

## 8. Границы этого слайса

Только mockup и его спецификация. Не реализуются и не проектируются: `CreateBackupOperation` и UI,
Staging-механизм и любой автоматический GC, S5 и политика проверки больших объёмов, изменения лимитов
16 МиБ, поддержка больших видео, background worker/foreground service, архитектура отмены, открытие
папки резервных копий, экран справки, PC/offload
и restore. Принятое ограничение (не решается здесь): обычное открытие экрана и обычный discovery в
будущем не должны требовать полного повторного SHA-чтения 20–50 ГБ медиа; выбор между presence+size,
явной проверкой по действию, ленивой и фоновой проверкой — предмет S5 и измерений.
