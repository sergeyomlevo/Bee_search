# Unified Territory Data Map — Layers/Filters, первый макет

Статус: PROPOSAL · не утверждено · ожидает решения владельца

## Контракт

PNG `unified-territory-layers-v1.png` и этот MD образуют один дизайн-контракт. PNG задаёт композицию,
плотность и расположение; MD — семантику, подписи и поведение. При существенной неоднозначности
решение не додумывается, а запрашивается у владельца. Pixel-perfect не требуется, если он ломает
Android accessibility, системные inset или адаптивность.

Макет — вариант дизайна, а не production-требование и не разрешение менять принятые решения.

## Опоры (не пересматриваются этим макетом)

- I016 (`docs/ideas.md`, Status `idea`) — цель: единая карта исследовательских данных Territory;
- D094 (`docs/decisions.md`, ACCEPTED) — один календарный диапазон; каждый тип фильтруется по своей
  canonical research date: `ObservationPoint` — дата наблюдения, `Hollow` / `LogHive` / `Apiary` —
  дата фиксации, `Inspection` — дата осмотра; это не вопрос существования объекта в периоде;
- `docs/architecture.md` §73.3 — MapLibre/Compose split остаётся design proposal, а не решением;
- `docs/ui/Создание интерфейсов.md` — mockup-first workflow;
- визуальный язык утверждённого `objects-ui-approved-v1.png` (тёплая поверхность, тот же primary).

## Варианты и выбранное направление

Рассматривались два варианта, оба исходят из существующего UI (один компактный icon-button со
`Surface` + `DropdownMenu`, нижняя панель `Объекты | Настройки`, статусные badges вверху слева).

**Вариант A (выбран) — одна панель «Слои и фильтры».** Точка входа — компактная пилюля `Слои` в
нижнем левом стеке контролов, над существующей кнопкой источника карты. Панель — частичный bottom
sheet: типы данных, период, `Сбросить` и `Готово`.

**Вариант B — постоянная строка чипов слоёв на карте + период в отдельном диалоге.** Плюс: переключение
в один тап. Минусы: постоянные контролы поверх карты (противные полевой задаче), ряд чипов не
вмещается при 5 типах и ломается при fontScale 1.7, дублирует существующий идиом «одна кнопка открывает
компактный список».

Причина выбора A: карта остаётся основным экраном, число постоянных контролов не растёт, панель
закрывается одним действием, композиция сохраняется при увеличенном системном шрифте.

## Экран и элементы

### 1/4 Обычная карта

Существующие элементы не меняются: статусные badges `DEV` · `4,6 м` · `z 15` вверху слева, GPS-точка,
красная точка центра, направляющая линия GPS → центр, кнопки `Вернуться к текущему местоположению` и
`Создать запись здесь` внизу справа, нижняя панель `Объекты | Настройки`, кнопка источника карты внизу
слева (три ромба).

Добавляется одна пилюля `Слои` (48 dp, ≥48 dp target) прямо над кнопкой источника карты. Позиция
существующей кнопки источника карты не меняется.

### 2/4 Панель открыта (по умолчанию)

Bottom sheet частичной высоты: drag handle, заголовок `Слои и фильтры`, явный `✕` в дополнение к
свайпу и тапу по затемнению. Карта остаётся видимой сверху и затемняется — состояние карты видно при
изменении настроек.

Разделы:

- `ДАННЫЕ НАБЛЮДЕНИЙ` — `Точки наблюдения`, `Дупла`, `Колоды`, `Пасеки` (переключатели), `Осмотры`
  (недоступная строка с пояснением `позже`);
- `ПЕРИОД` — строка текущего значения с `›`, быстрые варианты `Всё время` / `Текущий год` /
  `Текущий сезон`, поясняющая строка;
- нижние действия: `Сбросить` (текстовая, не destructive) и `Готово` (filled).

### 3/4 Панель с активным периодом

Показано состояние, когда период задан (`10.08.2026 — 01.09.2026` в строке значения, ни один preset
не выбран) и один тип отключён (`Колоды`). Это демонстрирует независимость слоёв и периода.

### 4/4 Результат на карте

Панель закрыта. Видны только включённые типы; пилюля `Слои` в активном состоянии (тонированный фон,
primary-обводка, точка-индикатор); в статусной колонке появился компактный чип периода
`Период: 10.08 — 01.09.2026  ✕`.

## Типы исследовательских данных

| Строка панели | Сущность | Маркер на карте | По умолчанию |
|---|---|---|---|
| `Точки наблюдения` | `ObservationPoint` | существующий круг с тоном `POSITIVE` / `NEGATIVE` / `UNRESOLVED` | включён |
| `Дупла` | `Hollow` | ромб, коричневый | включён |
| `Колоды` | `LogHive` | скруглённый квадрат, коричневый | включён |
| `Пасеки` | `Apiary` | шестиугольник, синий | включён |
| `Осмотры` | будущий `Inspection` | — | недоступна |

`Осмотры` показывается недоступной строкой с muted-пояснением `позже`: сущности ещё нет (D088, I009),
поэтому она не выдаётся за работающую функцию и ничего не рисует на карте.

Форма маркера различает типы, тон различает состояние точки; цвет не является единственным носителем
смысла. Существующее поведение маркеров точек (тон, доступность, выбор) сохраняется.

## Период

- Один календарный диапазон на все типы (D094).
- Значение по умолчанию — `Всё время`: ограничения нет, показывается весь набор.
- Тап по строке значения открывает выбор диапазона. Конкретный picker (Material3 `DateRangePicker`
  или эквивалент) этим макетом не фиксируется.
- Быстрые варианты — shortcuts: `Всё время`, `Текущий год`, `Текущий сезон`. При своём диапазоне ни
  один вариант не выбран, а строка значения показывает диапазон.
- Пояснение в панели: `Точки — по дате наблюдения, объекты — по дате фиксации.` Это компактная
  пользовательская формулировка D094, без существования/активности/подтверждённости.
- Не вводится UI для «существовал / активен / подтверждён / существование неизвестно»: это отдельная
  будущая аналитическая задача.

**Следствие для реализации (важно):** сегодня у `Hollow` / `LogHive` / `Apiary` нет поля даты фиксации
(`docs/data-model.md` §71.1). Поэтому период для объектов включается только после шага
«Design minimal fixation-date data-model change» из `docs/unified-territory-map-checklist.md`; до него
`created_at` не подписывается в UI как `дата фиксации` и не подменяет исследовательскую дату.

## Активное состояние фильтра

Минимум, не занимающий карту постоянно:

- пилюля `Слои` получает активный вид (тонированный фон, primary-обводка, точка-индикатор), когда
  скрыт хотя бы один тип или задан период;
- при заданном периоде в статусной колонке вверху слева появляется компактный чип
  `Период: 10.08 — 01.09.2026  ✕`; тап по чипу открывает панель, `✕` снимает только период;
- при состоянии по умолчанию (все доступные типы включены, `Всё время`) ни чипа, ни активного вида нет.

Доступность: состояние не передаётся только цветом или точкой — `contentDescription` пилюли называет
его словами, например `Слои и фильтры. Скрыты: Колоды. Период: 10 августа — 1 сентября 2026`.

Сверено с фактическим экраном DEV: статусная колонка вверху слева уже показывает строку
`DEV` · `точность` · `z` и вторую строку с измерением (`7,1 м · 67° СВ`), поэтому чип периода
размещается в той же колонке и при наличии измерения стоит вместе с ним (элементы стекаются, а не
заменяют друг друга).

## Сброс

`Сбросить` возвращает все доступные типы во включённое состояние и снимает период. Это не удаление
данных: исследовательские записи не меняются, подтверждение не требуется, действие визуально
нейтральное (не destructive).

## Закрытие и возврат к карте

Панель закрывается `Готово`, `✕`, свайпом вниз или тапом по затемнению. Выбор применяется сразу при
изменении (live), поэтому `Готово` только закрывает панель и возвращает полевой экран. После закрытия
карта показывает применённый набор данных и активное состояние фильтра.

## Доступность и полевые требования

- touch targets ≥ 48 dp, включая строки панели, переключатели, чипы периода и `✕`;
- panel скроллится и переносит chips при увеличенном системном fontScale; текст не обрезается и не
  ломается по буквам;
- один главный экран карты; постоянных контролов добавляется один (пилюля `Слои`);
- состояние карты понятно без открытия панели;
- сброс доступен в одно действие;
- research markers остаются Compose-маркерами с semantics и не переносятся в MapLibre (§73.3).

## Зарезервировано для будущих слоёв

I014 (пользовательские геопривязанные растры), I011 (GPX и пользовательская полевая геометрия),
I001 (аналитические слои) в этом макете **не показаны в UI**. Причина: показывать в production-панели
разделы, которых нет, — это служебная информация без пользы для полевого пользователя; владелец
явно допускает такой вариант. Информационная архитектура для них зарезервирована: каждый станет
отдельным разделом той же панели (растры — со своей видимостью и прозрачностью, полевая геометрия —
со своей группой, аналитика — после стабилизации базовой системы). Точное место и момент —
открытый вопрос, а не часть первого макета.

## Обратимое предположение о разделении с источником карты

Источник карты (`Онлайн карта` / `Векторная карта`, в DEV также `Спутник Sentinel` / `Гибрид`)
остаётся **отдельным** контролом с существующей позицией и существующим смыслом «Источник карты».
В макете он не объединён с панелью данных: это разные вопросы («какая подложка» и «какие данные
показаны»), и технические источники не должны становиться пунктами пользовательского списка данных.
Объединение возможно только при конкретной UX-причине и отдельном решении; production map modes этим
макетом не определяются.

## Mockup assumptions (обратимые предположения)

1. Точка входа — отдельная пилюля `Слои` над кнопкой источника карты; источник карты остаётся отдельно.
2. Подписи: `Слои` (кнопка), `Слои и фильтры` (заголовок панели).
3. Контейнер — modal bottom sheet частичной высоты; изменения применяются live; `Готово` закрывает.
4. По умолчанию включены все доступные типы, период — `Всё время`.
5. `Пасеки` — обычный переключатель; `Осмотры` — недоступная строка `позже`.
6. Формы маркеров: круг (точки, тон не меняется), ромб, скруглённый квадрат, шестиугольник.
7. Presets периода: `Всё время`, `Текущий год`, `Текущий сезон`; свой диапазон — через строку значения.
8. Активное состояние: тонированная пилюля + точка-индикатор + чип периода в статусной колонке.
9. Будущие разделы (I014, I011, I001) в UI не показываются до реализации.
10. Пояснительная полоса под фреймами на PNG — комментарий к макету, а не часть UI.

## Открытые вопросы владельцу

1. Точка входа: подписанная пилюля `Слои` (как на макете) или вторая icon-only кнопка в визуальном
   языке существующей кнопки источника карты?
2. `Пасеки` — рабочий переключатель уже сейчас (как на макете) или тоже недоступная строка, пока у
   Apiary нет пользовательского жизненного цикла?
3. Период для объектов: выпускать фильтр только для точек до появления fixation-date полей, или
   панель и data-model изменение идут одним шагом?
4. Базовая карта: оставить отдельным контролом (рекомендация макета) или перенести в раздел панели?
5. Показывать ли зарезервированные разделы (I014 / I011 / I001) в production-панели как недоступные
   группы, или держать их только в спецификации до реализации (рекомендация макета)?

## Что макет не определяет

Окончательные названия map modes; судьбу `ONLINE` / `VECTOR` / `SENTINEL`; финальный набор и порядок
кнопок; конкретный компонент выбора диапазона; финальную графику маркеров; правила порядка слоёв;
performance limits; статус §73.3; schema, migration и implementation.

Фон карты на PNG — условная иллюстрация (цвета offline-vector style), а не выбор подложки: макет не
назначает map mode по умолчанию и не показывает конкретный источник как обязательный.
