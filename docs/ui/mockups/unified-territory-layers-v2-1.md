## Owner decisions (зафиксированы при approval 2026-10-02)

Ниже — утверждённые положения. Этот документ их не пересматривает, а применяет.

**Entry point**

1. отдельной кнопки «Слои» над картой нет;
2. вход в управление research-data display — в существующей нижней панели;
3. entry point — Material `visibility` (глаз), пользовательский смысл «Данные на карте»;
4. basemap/source selector остаётся отдельным контролом.

**Типы данных**

5. каждый доступный тип имеет независимо visibility и filters; это разные состояния;
6. visibility OFF скрывает тип и **не** уничтожает его filters;
7. visibility ON возвращает тип с ранее установленными filters;
8. filters принадлежат конкретному типу; одного универсального набора filters для всей карты нет;
9. разные типы одновременно могут иметь разные значения filters.

**Аккордеон-модель**

10. экран типа — список filters этого типа;
11. каждый filter — compact accordion section: свёрнутый показывает имя, сводку значения и
    стандартный expand affordance; раскрытый добавляет полноценный editor внутри секции;
12. пока реально определён только `Период`; дополнительные тип-специфичные filters могут появляться
    позже как sibling accordion sections;
13. фиктивные placeholders в production UI не показываются.

**Календарь**

14. у каждого типа может быть собственный calendar filter;
15. на каждом уровне — одно правило: одна единица времени **или** один непрерывный диапазон;
16. уровни: `Год` (`2026`, `2024–2026`), `Месяц` (`август 2026`, `август–сентябрь 2026`, cross-year
    вида `декабрь 2025 – февраль 2026` моделью не запрещается), `День` (`17.08.2026`,
    `10.08.2026–01.09.2026`);
17. на тип приходится **one contiguous interval**; disjoint intervals в модель не входят;
18. период одного типа не влияет на другой.

**Состояние и сброс**

19. на основной карте нет period chips;
20. если скрыт хотя бы один доступный тип или активен хотя бы один filter, bottom-bar action
    получает compact state indicator; подробные значения видны после входа в «Данные на карте»;
21. `Сбросить период` снимает период только текущего типа и не меняет visibility;
22. global `Сбросить фильтры` **оставлен**: снимает filters всех доступных типов и не меняет
    visibility;
23. никакой reset не удаляет research data.

**Прочее**

24. `Apiary` / «Пасеки» и будущий `Inspection` / «Осмотры» **не показываются в панели вообще**, пока
    соответствующая пользовательская функциональность недоступна — не показываются даже disabled
    rows; из conceptual architecture и из I016 они не удаляются, их будущее появление не отрицается;
25. строки типов появляются в панели только тогда, когда capability становится доступной;
26. Unified Territory Data Map в целевом направлении показывает research objects на общей карте;
    текущее observed ограничение (markers только в отдельном browser mode) — описание CURRENT
    IMPLEMENTATION, а не будущий UI requirement; production map modes сейчас не меняются;
27. I014 / I011 / I001 не показываются как работающие функции;
28. `created_at` не подменяет fixation/research date; canonical research date по D094 сохраняются.

## Аккордеон: affordance и Material convention

Смотрелся актуальный Material pattern для раскрывающихся строк (списки Material 3, expandable list
item; `ExpansionTile` в Material-реализации Flutter как эталонное поведение trailing-иконки; Android 16
добавляет accessibility API для передачи expanded/collapsed состояния). Вывод: expand/collapse
показывается **вертикальным** шевроном (`expand_more`/`expand_less`), который при раскрытии
разворачивается на 180°, а не отдельной нестандартной стрелкой.

Поэтому в V2.1 два визуально разных affordance, и они не смешиваются:

| Уровень | Действие | Affordance |
|---|---|---|
| LEVEL 1 — строка типа в панели | перейти к фильтрам этого типа | горизонтальный шеврон `›` |
| LEVEL 2 — строка фильтра на экране типа | раскрыть/свернуть редактор на месте | вертикальный шеврон `⌄` / `⌃` |

Строка фильтра имеет: название фильтра, компактную сводку текущего значения, стандартный
expand/collapse affordance, touch target ≥ 48 dp и accessibility-состояние «развёрнуто» /
«свёрнуто» (`stateDescription` и expand/collapse-семантика; точный API — деталь реализации).

## Карта и нижняя панель

### Основной экран

Ничего в существующем экране не меняется: статусная колонка вверху слева, GPS-точка, точка центра,
направляющая линия, контролы внизу справа, селектор источника карты внизу слева (три ромба, отдельный
контрол и отдельный вопрос «какая подложка»). Никаких дополнительных контролов над картой нет, чипов
периода нет.

Нижняя панель — тот же `Surface`, высота 56 dp, `Arrangement.End`, три 48 dp действия:
`Объекты` · **действие отображения (Material `visibility`)** · `Настройки`. Точный финальный порядок
остаётся деталью UI-спецификации.

`contentDescription` действия: «Данные на карте», при активных ограничениях — со словами о состоянии
(«Данные на карте. Есть активные ограничения отображения.»). Точная строка не является финальной
copy; она обязана быть понятной без иконки.

### Состояние

- индикатор (небольшая точка) горит, если скрыт хотя бы один доступный тип **или** хотя бы у одного
  типа период отличается от «всё время»;
- при состоянии по умолчанию индикатора нет;
- состояние не передаётся только цветом: оно всегда продублировано словами в `contentDescription`;
- сводка периодов на карте не показывается: периоды независимы, у них больше нет одного общего
  значения, а пять сводок заняли бы карту.

## Панель «Данные на карте»

Modal bottom sheet: drag handle, заголовок «Данные на карте», `✕`. Карта остаётся видимой сверху и
затемняется — состояние карты видно при изменении настроек.

Состав:

- раздел `ИССЛЕДОВАТЕЛЬСКИЕ ДАННЫЕ` — **только доступные** типы данных;
- у каждого типа: `switch` видимости · название · сводка фильтров · горизонтальный шеврон;
- нижние действия: `Сбросить фильтры` (глобальный, не destructive) и `Готово`.

Кадр C показывает состояние: `Точки наблюдения` включены, период `2024–2026`;
`Дупла` выключены, период `авг–сен 2026` сохранён и показан muted; `Колоды` включены, `всё время`.
Других строк в панели нет — см. правило доступности ниже.

Сводка фильтров на строке типа — **сводка, а не редактор**: она не раскрывается и не заменяет переход
в фильтры типа. Правило цвета сводки: primary, если у видимого типа период отличается от `всё время`;
muted во всех остальных случаях (тип скрыт, периода нет).

## Видимость

- видимость меняет только `switch`; тап по названию не делает ничего скрытого;
- включение типа не сбрасывает и не задаёт его фильтры;
- выключение типа не сбрасывает его фильтры: сводка остаётся на строке в muted-виде;
- повторное включение возвращает ровно прежнее состояние фильтров;
- отдельного действия «показать все скрытые» не вводится: включить тип — один тап по его `switch`.

## Экран типа = список фильтров

Экран типа открывается горизонтальным шевроном строки. Это тот же контейнер с заголовком-именем типа
и стрелкой назад; отдельного экрана навигации не появляется.

**Аккордеон-модель.** Каждый реальный фильтр типа — одна compact accordion row.

- Свёрнутая строка: `Период · <сводка>` + вертикальный шеврон вниз. Редактора на экране нет.
- Раскрытая строка: та же строка со шевроном вверх, а под ней — полный редактор этого фильтра.
- Тип с не заданным фильтром показывает `Всё время` в сводке.
- **Mockup assumption:** одновременно раскрыт максимум один фильтр. Раскрытие другого сворачивает
  предыдущий. Причина — полевой mobile UI: меньше прокрутки и визуального шума. Это предположение
  макета, а не архитектурный инвариант; при появлении нескольких фильтров поведение можно пересмотреть.
- **Mockup assumption:** пока «Период» — единственный определённый фильтр, при первом входе на экран
  типа он раскрыт. Свёрнутое состояние достигается одним тапом по строке фильтра. Когда фильтров
  станет несколько, состояние по умолчанию пересматривается.

**Расширяемость.** Дополнительные тип-специфичные фильтры могут появиться позже как соседние
accordion-секции того же экрана. В production-facing макете они **не нарисованы**: ни «Фильтр 2», ни
пустых строк, ни placeholder-контролов. Место расширения описано здесь, а не показано фиктивным
элементом UI.

**«Сбросить период»** живёт внутри раскрытой секции фильтра и сбрасывает только период этого типа.
Отдельное «Сбросить фильтры типа» сейчас не рисуется: пока фильтр один, оно дублировало бы
«Сбросить период».

## Календарная модель: одно правило на всех уровнях

На каждом уровне пользователь выбирает **одну единицу времени** или **один непрерывный диапазон**.
Mental model одинаков для года, месяца и дня.

| Уровень | Одна единица | Непрерывный диапазон |
|---|---|---|
| `Год` | `2026` → 01.01.2026 — 31.12.2026 | `2024–2026` → 01.01.2024 — 31.12.2026 |
| `Месяц` | `август 2026` → 01.08.2026 — 31.08.2026 | `авг–сен 2026` → 01.08.2026 — 30.09.2026 |
| `День` | `17.08.2026` → этот день | `10.08.2026 — 01.09.2026` → точный диапазон |

Правила:

- точность выбирается явно (`Год | Месяц | День`), приложение не угадывает её по нажатию; начальная
  точность при входе — `Год`;
- нормализация всегда даёт один интервал: от начала первой единицы до конца последней;
- диапазон может пересекать границу месяца и года: `декабрь 2025 – февраль 2026` не запрещается
  моделью; на уровне «День» диапазон `10.08.2026 — 01.09.2026` пересекает границу месяца;
- смена точности сохраняет текущее значение периода, а не сбрасывает его;
- **disjoint-периоды не поддерживаются**: «май + сентябрь без июня–августа» и «2024 + 2026 без 2025»
  одной моделью не выражаются. Тип имеет **один непрерывный интервал**; множественные независимые
  интервалы — отдельная потенциальная будущая возможность, требующая другой модели фильтра;
- на уровне «Месяц» выбор — непрерывный ряд: тап по соседнему месяцу продолжает ряд, тап по
  не-соседнему начинает новый ряд вместо старого; тап по единственной выбранной единице снимает
  период и возвращает `Всё время`;
- на уровне «День» первый выбор — начало, второй — конец; если второй раньше первого, диапазон
  нормализуется;
- время суток в фильтр не входит: исследовательская дата — дата, а не момент времени;
- конкретный компонент (Material `DatePicker`/`DateRangePicker` с обвязкой уровней или собственный
  календарь) этим макетом не фиксируется.

## Тип-специфичные периоды

Одновременно допустимо и является нормальным состоянием:

| Тип | Видимость | Период |
|---|---|---|
| `Точки наблюдения` | включён | `2024–2026` |
| `Дупла` | выключен | `авг–сен 2026` (сохранён) |
| `Колоды` | включён | `всё время` |

Каждый тип применяет свой период к **своей** canonical research date (D094 §2): точки — по дате
наблюдения, дупла и колоды — по дате фиксации, будущий осмотр — по дате осмотра. Отсутствие периода
означает отсутствие временного ограничения для этого типа, а не «период по умолчанию».

**Следствие для реализации (важно и не решается этим макетом):** сегодня у `Hollow` / `LogHive` /
`Apiary` нет поля даты фиксации (`docs/data-model.md` §71.1). Поэтому период для объектов включается
только после шага «Design minimal fixation-date data-model change» из
`docs/unified-territory-map-checklist.md`; до него `created_at` не подписывается в UI как «дата
фиксации» и не подменяет исследовательскую дату.

## Сброс

| Действие | Где | Что делает | Чего не делает |
|---|---|---|---|
| `Сбросить период` | внутри раскрытой секции фильтра | снимает период **этого типа** → `всё время` | не меняет видимость и не трогает другие типы |
| `Сбросить фильтры` | панель «Данные на карте» | снимает периоды у всех типов → `всё время` | не включает и не выключает ни один тип |

Никакое действие сброса не удаляет исследовательские данные, не требует подтверждения и визуально
нейтрально (не destructive).

## Правило доступности типов в панели

Панель показывает **только те типы, у которых есть доступная пользователю функциональность**. Тип,
который существует в данных/архитектуре, но не имеет пользовательского жизненного цикла, в панели не
показывается вообще — в том числе не показывается disabled-строкой. Строка типа появляется тогда и
только тогда, когда capability становится доступной.

Фактическое состояние на момент approval (проверено по коду, не по документам):

| Сущность | Есть | Нет |
|---|---|---|
| `Apiary` (Пасеки) | таблица/подтип, domain-модель, backup, часть repository API | создание (`MainViewModel.kt:141`, `PhysicalObjectCreationViewModel.kt:158`, `PhysicalObjectCreationRoute.kt:120` → `error("Apiary creation is not part of this flow")`), открытие списка (`MainActivity.kt:227-228` — только `onOpenHollows` / `onOpenLogHives`), карточка, медиа, экспорт (`PhysicalObjectExportValidator.kt:60`: «no creation, card or media lifecycle yet») |
| `Inspection` (Осмотры) | ничего в `app/src/main/java` | сущности нет вообще |

Следствие для панели: строк `Пасеки` и `Осмотры` в ней сейчас **нет**. Это owner correction к
просмотренному PNG, где они ещё присутствовали как disabled rows; просмотренный вариант не является
утверждённым артефактом и в репозитории не сохранён (см. раздел о correction выше), отдельная
итерация макета не создавалась.

Из **conceptual architecture** Unified Territory Data Map обе сущности не удалены и в I016 остаются:
они появятся как рабочие строки панели, когда у них появится пользовательский жизненный цикл и (для
периода) дата фиксации или дата осмотра. Отказ показывать строку — не отрицание их будущего, а отказ
обещать несуществующую функцию.

## Доступность и полевые требования

- touch targets ≥ 48 dp: действие в нижней панели, строки типов, `switch`, горизонтальные и
  вертикальные шевроны, месяцы, годы, дни, обе нижние кнопки;
- состояние не передаётся только цветом: индикатор на действии дублирован словами; скрытый тип
  различим и по `switch`, и по тексту; раскрытый фильтр сообщает «развёрнуто»/«свёрнуто»;
- строка фильтра не имеет фиксированной высоты: при увеличенном системном `fontScale` значение
  переносится на вторую строку, и строка растёт — значение не обрезается и не сталкивается с
  названием фильтра;
- сетки месяцев и годов при увеличенном шрифте перестраиваются в меньшее число колонок; панель
  скроллится;
- солнце и перчатки: крупные цели, никаких hover- и long-press-действий;
- постоянных контролов на карте не добавляется ни одного;
- research markers остаются Compose-маркерами с semantics и не переносятся в MapLibre (§73.3);
- offline: панель, экран типа и календарь не требуют сети и не зависят от источника карты.

## Сценарии

1. **Точки наблюдения = 2026.** Экран типа → «Период» → `Год` → `2026`. Точки вне 2026 не
   показываются; видимость и периоды других типов не меняются.
2. **Точки наблюдения = август 2026.** `Месяц` → `авг`. Значение `авг 2026`.
3. **Точки наблюдения = авг–сен 2026.** `Месяц` → `авг` + `сен` подряд → один интервал
   01.08.2026 — 30.09.2026.
4. **Точки наблюдения = 10.08.2026 — 01.09.2026.** `День` → `10` в августе → переход к сентябрю →
   `1`. Диапазон пересекает границу месяца.
5. **Точки наблюдения = 2024–2026.** `Год` → `2024` + `2025` + `2026` подряд → 01.01.2024 —
   31.12.2026 (кадр F).
6. **Смешанные периоды типов.** `Точки наблюдения` = `2024–2026`, `Дупла` = `авг–сен 2026`,
   `Колоды` = `всё время` одновременно (кадр C).
7. **Скрытый тип с сохранёнными фильтрами.** `Дупла` выключены, период `авг–сен 2026` сохранён и
   показан muted. Повторное включение возвращает ровно `авг–сен 2026`.
8. **Свёрнутый и раскрытый «Период»** на одном и том же типе: свёрнутый показывает только сводку
   (кадр D), раскрытый — редактор (кадр E).
9. **Попытка disjoint-периода.** Выбор `май` и `сентябрь` без июня–августа этой моделью не
   выражается: второй тап по не-соседнему месяцу начинает новый ряд вместо старого.

## Стоимость в жестах

Закрытие панели — `Готово`, свайп вниз, системный «назад» или тап по затемнению, то есть один жест.

**Owner clarification 2026-10-10.** Панель — одна сессия настройки: ни одно изменение внутри неё
(видимость, период, `Сбросить период`, `Сбросить фильтры`) её не закрывает. `Готово` на экране типа
завершает настройку этого типа и возвращает к списку типов, а не на карту; закрывают панель только
`Готово`/`✕` в самой панели, системный Back со списка типов, свайп и тап по затемнению. Поэтому в
таблице ниже «закрыть» означает шаг из списка типов: со экрана типа перед ним стоит `Готово` или Back.
Один корневой дефект этого поведения (панель закрывалась после каждого изменения) разобран в
`.agent/handoff.md`.

| Задача | Жесты | Разбор |
|---|---|---|
| Скрыть `Дупла` | 3 | действие · `switch` `Дупла` · закрыть |
| Точки = `2026` | 4 | действие · шеврон строки · `2026` · закрыть (`Год` — точность по умолчанию) |
| Точки = `2024–2026` | 6 | действие · шеврон · `2024` · `2025` · `2026` · закрыть |
| Точки = `авг 2026` | 5 | действие · шеврон · `Месяц` · `авг` · закрыть |
| Точки = `авг–сен 2026` | 6 | действие · шеврон · `Месяц` · `авг` · `сен` · закрыть |
| Точки = `10.08.2026 — 01.09.2026` | 7 | действие · шеврон · `День` · `10` · `›` · `1` · закрыть |
| Свернуть раскрытый «Период» | +1 | тап по строке фильтра; экран типа при этом компактен (кадр D) |
| Снять период только у одного типа | +1 | «Сбросить период» внутри раскрытой секции |
| Вернуться к «без периодов» | 3 | действие · `Сбросить фильтры` · закрыть |

Точность по умолчанию — `Год`; самому частому полевому вопросу «этот сезон» соответствует минимум
жестов.

## Согласованность кадров

Кадры C, D и E описывают одно синхронное состояние: `Точки наблюдения` = `2024–2026`, `Дупла`
выключены с сохранённым `авг–сен 2026`, `Колоды` = `всё время`.

Кадры F, G и H — примеры **каждого уровня** календаря (год-диапазон, один год, день-диапазон), а не
одно синхронное состояние: они показывают поведение одного и того же контрола в разных режимах
точности. Это указано и в подписях под кадрами.

Маркеры на кадрах — условная иллюстрация состава данных, а не утверждение о количестве записей.
Пасек на карте нет: их нельзя создать, поэтому и маркеров пасек в макете нет.

## Mockup assumptions (обратимые предположения)

1. Действие отображения — третье в нижней панели, Material `visibility`, заголовок «Данные на карте».

5. Строка типа = `switch` · название · сводка фильтров · горизонтальный шеврон.
6. Экран типа = список фильтров; «Период» — accordion row; редактор только внутри раскрытой секции.
7. Одновременно раскрыт максимум один фильтр; «Период» раскрыт по умолчанию при первом входе.
8. Дополнительные тип-специфичные фильтры появятся позже как соседние accordion-секции и сейчас не
   рисуются.
9. Период типа — один непрерывный интервал; disjoint-периоды не поддерживаются.
10. Единое правило «одна единица или один непрерывный диапазон» на всех уровнях календаря.
11. Список доступных лет строится из годов, в которых есть записи этого типа; если записей нет,
    доступно только `Всё время`.
12. В панели показываются только типы с доступной пользовательской функциональностью; тип без
    жизненного цикла не показывается даже disabled-строкой.
13. Активное состояние — только индикатор на действии; сводки периодов на карте нет.
14. Пояснительные полосы под кадрами — комментарии к макету, а не часть UI.
