# Objects UI — утверждённая спецификация
Статус: APPROVED · 2026-09-25

## Контракт
PNG и этот MD образуют единый UI-контракт. PNG задаёт композицию, плотность и расположение; MD — семантику и поведение. При существенной неоднозначности агент не додумывает, а запрашивает уточнение. Pixel-perfect не требуется, если он ломает Android accessibility, системные inset или адаптивность.

## Создание
Тип объекта выбирается ДО формы через `+` на карте. Поэтому форма Дупла не содержит `Дупло / Колода` и повторный выбор типа. Координаты также выбираются до формы существующим map-center confirmation flow и в форме не дублируются. Заголовок ещё не сохранённой формы — `Новое дупло` или `Новая колода`; форма начинается с `Дерево`. Настоящее обозначение `Дупло N` / `Колода N` появляется только после успешного создания authoritative numbering mechanism. Отмена не расходует номер. `Дупло 1` на PNG — визуальный пример композиции заголовка уже идентифицированного объекта, а не preview или ранняя резервация номера.

Порядок: Дерево → Направление летка → Высота летка → Наружный диаметр → Внутренний диаметр (необязательно) → Дополнительно → Медиа (необязательно) → Отмена/Сохранить. Существующая Objects V1 validation сохраняется.

## Азимут
Азимут — обычное компактное однострочное редактируемое числовое поле 0–359°. Рядом/под ним показывается сторона света. HeadingProvider остаётся источником live-компаса; есть компактное действие фиксации текущего показания. Пользователь может коснуться числа, поставить курсор, стереть автоматическое значение и вручную ввести нужное. После ручной правки live heading не должен сам перезаписывать введённое. Сохраняется итоговый numeric azimuth. Существующие true-heading/GeomagneticField и accuracy warning не ухудшаются. Не возвращать громоздкую комбинацию «текущее + зафиксировано + Измерить снова + отдельное узкое manual-поле».

## Медиа
Media показывается визуально, а не списком имён файлов. Фото — миниатюра. Видео — миниатюра/preview с признаком видео. У каждого item маленький `×` в углу миниатюры; отдельная кнопка `Удалить` не нужна. `×` удаляет item с сохранением существующей безопасной media semantics. Поддержка нескольких image/video items сохраняется. Добавление — камера и системный picker; допустим компактный `+` или отдельный компактный режим, как на mockup. Не создавать вторую media-модель.

В карточке сохранённого объекта media обязательно видимо: основное media крупно, остальные через миниатюры/галерею; фото и видео различимы и доступны для просмотра.

## Просмотр и редактирование
Карточка `Дупло N` — пользовательское представление, не technical dump. Компактно показывать media, дерево, азимут+сторону, высоту летка, наружный/внутренний диаметры, заметки, координаты, Territory, creator, created-at.

Характеристики редактируемы. Допустим общий Edit mode вместо карандаша у каждой строки. Координаты также редактируются ИЗ просмотра существующего объекта через переиспользование существующего map-center confirmation/location flow. Не создавать вторую location framework. Редактирование не меняет stable UUID, type, Territory, creator, created-at или sequence/designation. Есть `Показать на карте`.

Координаты в UI выводить с разумной полевой точностью, не длинным decimal dump; persistence precision не снижать.

## FontScale — обязательная приёмка
Реализация должна сохранять композицию при реальном системном fontScale Samsung:
- никакого вертикального текста из букв;
- основные действия читаются целиком;
- числовые поля однострочные;
- блок азимута компактный;
- media thumbnails сохраняют пропорции, `×` остаётся в углу;
- при нехватке ширины переносить/перекомпоновывать целые элементы, а не ломать слова;
- вертикальная прокрутка допустима;
- нижние действия не перекрывают содержимое;
- не решать проблему чрезмерным уменьшением текста.

## Не менять без доказанной необходимости
Room v9/schema/migration, D088 identity, repositories, Complete Backup v4, media persistence/staging/SHA-256, observer provenance, HeadingProvider math, numbering, chooser `+ → type`, creation coordinate flow, Stable/Beta/version metadata. Не добавлять Inspection, GPX/track и новые object types.

## Визуальная приёмка
После реализации одних зелёных тестов недостаточно. Установить DEV preserving data; проверить форму на Samsung с реальным fontScale; сделать скриншоты формы с азимутом/media; создать или открыть объект с фото и по возможности видео; сделать скриншот карточки; сравнить с утверждённым PNG. PASS требует отсутствия вертикального текста/сломанных кнопок и сохранения общей композиции mockup.
