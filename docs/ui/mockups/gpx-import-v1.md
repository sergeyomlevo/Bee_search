# Импорт GPX — макет v1 (ревизия навигации)

**Статус:** APPROVED для реализации · OWNER decision 2026-10-17.
Утверждён владельцем как основа UI-реализации импорта GPX; композиция и правила
не меняются. Stage1 и H05 остаются OPEN.

**Визуальный эталон:** `gpx-import-v1.png` — один storyboard, 9 кадров.
**Файлы:** `gpx-import-v1.png` (композиция) и этот MD (семантика, тексты, состояния, поведение).

Этот документ следует [mockup-first workflow](../Создание%20интерфейсов.md): PNG задаёт расположение
и визуальную иерархию, MD — смысл, данные и поведение. При расхождении действует это разделение.
Макет не является pixel-perfect контрактом: Android-адаптивность, системные inset, доступность и
реальный `fontScale` сохраняются.

Связанные действующие документы:

- [D106 Stage 1A, §10 «Visibility and UI»](../../d106-stage1-gpx-spec.md) — вход
  `Визуализация → Данные на карте`, минимальная GPX-секция, capture до picker, progress/Cancel,
  успех только после READY;
- [D106 GPX activation gate corrected](../../decisions.md#d106-gpx-activation-gate-corrected--owner-decision-2026-10-17) —
  пользовательский импорт больше не ждёт отдельного GPX protection Slice; production UI требует
  утверждённого mockup PNG+MD;
- [.agent/ui-policy.md](../../../.agent/ui-policy.md) — тексты, fontScale, 48 dp, feedback, semantics;
- [mockup-first workflow](../Создание%20интерфейсов.md) — процесс утверждения UI;
- `docs/ui/mockups/unified-territory-layers-v2-1.md` — визуальный язык панели «Данные на карте»;
- `docs/ui/mockups/backup-v2.md` — визуальный язык success/error-состояний.

## 1. Назначение

Добавить в Bee Search **раздел GPX** с двумя самостоятельными действиями:

```text
Визуализация → Данные на карте → Треки GPX → Импорт GPX → Android picker
Визуализация → Данные на карте → Треки GPX → Показать трек
```

- **Импорт GPX** — добавить GPX-файл из памяти телефона и сохранить его в текущей Territory.
- **Показать трек** — будущий переход к списку сохранённых треков и управлению их отображением
  на карте. В этом макете функция обозначена, но не реализуется.

Импорт — это сохранение данных, а **не** их показ на карте. Импорт не включает отображение;
отображение пользователь включает отдельно; отключение отображения не удаляет импортированный
файл. Список треков, hide/show, Registry и рендеринг реализуются отдельным этапом.

## 2. Границы макета

Входит:

- новая структура раздела GPX в существующей панели «Данные на карте»;
- вложенная страница «Треки GPX» с двумя действиями;
- импорт: захват Territory/Observer, системный picker, прогресс, отмена, дубликат, успех,
  ошибки;
- семантика отмены при уже сохранённом результате;
- возврат из picker, recreation, повторное открытие приложения;
- fontScale 1.7.

Не входит:

- список импортированных GPX, выбор одного/нескольких треков, hide/show, Registry, карта;
- Backup/Restore, Android Auto Backup, защита/восстановление GPX;
- удаление, переименование, экспорт, share, multi-file import;
- изменение Territory/Observer и любые их настройки;
- production-код, Room, parser, Coordinator, флаги активации.

## 3. Навигация

### 3.1. Основная панель «Данные на карте»

Порядок:

1. заголовок `Данные на карте`, `✕`;
2. секция `ИССЛЕДОВАТЕЛЬСКИЕ ДАННЫЕ`;
3. существующие строки `Точки наблюдения`, `Дупла`, `Колоды`;
4. существующие действия `Сбросить фильтры` / `Готово` — завершают блок исследовательских данных;
5. визуальный горизонтальный разделитель;
6. самостоятельная секция `GPX`;
7. строка навигации `Треки GPX` с подписью `Импорт и показ сохранённых треков`.

**Уточнение OWNER 2026-10-18:** действия исследовательских данных находятся перед разделителем
и GPX, не дублируются и сохраняют поведение. Вся основная панель прокручивается вертикально;
при `fontScale 1.7` раздел GPX остаётся доступен прокруткой. Отдельного закреплённого footer,
нового экрана или дополнительного bottom sheet не появляется.

На основной панели **нет** действия `Импорт GPX`. Строка `Треки GPX` — обычный пункт навигации
с иконкой маршрута и стрелкой перехода, а не `switch` отображения. Пятой зоны toolbar и кнопки
поверх карты нет.

### 3.2. Вложенная страница «Треки GPX»

Открывается в том же bottom sheet, без нового route приложения:

- заголовок `Треки GPX`;
- стрелка возврата к основной панели `Данные на карте`;
- две строки в следующем порядке.

**Первое действие — `Импорт GPX`**

- подпись: `Добавить GPX-файл из памяти телефона`;
- иконка upload;
- стрелка перехода;
- открывает системный Android picker и запускает импорт.

**Второе действие — `Показать трек`**

- подпись: `Выбрать сохранённый трек для карты`;
- отдельная иконка карты/маршрута;
- стрелка перехода;
- помечено `Скоро`.

`Показать трек` — предусмотренная следующая функция, а не работающая пустая кнопка. В import
Slice строка видна, но не открывает пустой экран: она недоступна и имеет бейдж `Скоро`.
Активной она становится только вместе со следующим UI Slice списка и видимости треков. Дизайн
этого списка, hide/show и Registry в задание не входит.

Обе строки имеют разные иконки и стрелки перехода (у будущей — приглушённая).

### 3.3. Back

| Где | Поведение |
|---|---|
| вложенная страница | стрелка `←` и системный Back возвращают к основной панели; панель остаётся открытой |
| основная панель | Back, свайп, тап по затемнению, `✕`, `Готово` закрывают панель на карту |
| picker | отмена возвращает на вложенную страницу без сообщений |
| импорт | Back и `Отмена` запускают проверку результата (см. §7) |
| результат | Back/свайп/`Готово`/`Закрыть` закрывают панель на карту |

## 4. Принцип: хранение и видимость

OWNER установил:

- GPX можно импортировать и сохранить, не отображая на карте;
- импорт сам по себе не включает отображение;
- отображение пользователь включает отдельно;
- отключение отображения не удаляет импортированный файл;
- впоследствии можно выбрать один или несколько сохранённых треков для показа на карте;
- настройку видимости желательно сохранять между запусками (техническая модель в этом задании
  не проектируется).

Следствие для UI: успех импорта не содержит действия «Показать на карте» и не запускает карту.
Он сообщает факт сохранения и границу: `На карте данные пока не отображаются.`

## 5. Импорт

```text
Треки GPX → Импорт GPX → системный picker → импорт → дубликат (если нужно) → успех/ошибка
```

Перед открытием picker фиксируются текущая Territory, Observer (nullable) и новый запрос.
Picker получает уже зафиксированный контекст; импорт никогда не переносится на другую Territory.

Один GPX-файл может содержать несколько треков, маршруты или точки. Тексты не подразумевают
«один файл = один трек»: используются `GPX-файл`, `данные`, `содержимое`. Слово «трек» остаётся
только в утверждённых названиях `Треки GPX`, `Показать трек` и подписи
`Выбрать сохранённый трек для карты`.

Прогресс неопределённый; показываются имя файла, целевая Territory и короткая фаза:
`Читаем файл…` → `Проверяем данные…` → `Сохраняем GPX…`. Проценты, байты, число точек, SHA и
внутренние идентификаторы не показываются.

## 6. Системный picker

- Стандартный Android `OpenDocument`, без собственного файлового экрана.
- MIME-фильтр не навязывается (`*/*`): приложение проверяет содержимое само.
- Нажатие на файл **завершает** выбор; отдельной команды «Загрузить», «Открыть», «ОК» или
  дополнительного подтверждения нет.
- В кадре нет предварительного синего выделения строки и синей галочки: это создавало бы
  впечатление, что файл только выделен и требует ещё одной команды.
- Отмена picker возвращает на вложенную страницу без сообщения об ошибке.

Точная подпись под кадром (не удлинять):

```text
Для импорта нажмите на нужный файл
```

## 7. Отмена и уже сохранённый результат

Отмена не должна объявлять импорт отменённым, если файл уже сохранён. Поведение:

1. Пользователь нажимает `Отмена` или Back во время импорта, либо ответ был потерян.
2. UI не показывает карточку отмены сразу. На той же поверхности отображается состояние
   `Проверяем результат…`; `Отмена` недоступна.
3. Результат устанавливается существующими Workflow/Coordinator и durable request correlation;
   новая state machine не вводится.
4. Если результат уже сохранён (READY committed) — показывается успех
   `GPX-файл импортирован`, даже если ответ первоначально не был доставлен или текущие
   настройки успели измениться.
5. Если подтверждено, что сохранения не было, — показывается нейтральное `Импорт отменён` /
   `Файл не был добавлен.`
6. Если результат пока не определён — нельзя показывать ни ложный успех, ни ложную отмену.
   При недоступной проверке: `Не удалось проверить результат` / `Проверить снова` / `Закрыть`.
7. Изменение текущей Territory не переносит уже созданный запрос на другую территорию. Если
   импорт завершён в ранее зафиксированной Territory, успех показывает именно её; смена текущих
   настроек не превращает результат в отмену. Если импорт не завершён и контекст стал
   недействительным — только нейтральная отмена без retargeting.
8. Повторная проверка использует существующую корреляцию; новый импорт и новый request при этом
   не создаются.

## 8. Состояния

Номера ниже — инвентарь состояний; кадры PNG пронумерованы отдельно.

| № | Состояние | Что видно | Действия |
|---|---|---|---|
| 1 | Основная панель | действия исследовательских данных → разделитель → секция GPX; строка `Треки GPX` | открыть `Треки GPX` |
| 2 | Вложенная страница | `Треки GPX`, `←`; `Импорт GPX`; `Показать трек` + `Скоро` | `Импорт GPX`; будущее `Показать трек` недоступно |
| 3 | Picker | системный Android picker, обычный список | нажать файл / отменить |
| 4 | Импорт | spinner, `Импорт GPX…`, файл, территория, фаза | `Отмена` |
| 5 | Дубликат | диалог поверх прогресса | `Импортировать ещё раз` / `Не импортировать` |
| 6 | Успех | `GPX-файл импортирован`, файл, территория, граница показа | `Импортировать ещё` / `Готово` |
| 7 | Успех с предупреждением | то же + янтарный блок | те же |
| 8 | Ошибка | красный `!`, заголовок, файл, причина | `Выбрать другой файл` / `Закрыть` |
| 9 | Проверка результата | состояние `Проверяем результат…` | нет |
| 10 | Отмена | нейтрально, `Импорт отменён` | `Готово` |
| 11 | Дубль отклонён | нейтрально, `Импорт не выполнен` | `Готово` |
| 12 | Контекст изменён | нейтрально, `Импорт отменён`, `Территория изменилась` | `Готово` |
| 13 | Проверка не удалась | нейтрально, `Не удалось проверить результат` | `Проверить снова` / `Закрыть` |

Переходы:

```text
Основная панель --Треки GPX--> Вложенная страница
Вложенная страница --стрелка/Back--> Основная панель
Вложенная страница --Импорт GPX--> capture --> Picker
Picker --отмена--> Вложенная страница (без сообщения)
Picker --файл--> Импорт
Импорт --успех--> Успех / Успех с предупреждением
Импорт --ошибка--> Ошибка
Импорт --дубликат--> Дубликат
Дубликат --подтверждение--> Импорт --> Успех
Дубликат --отказ--> Дубль отклонён
Импорт --Отмена/Back--> Проверка результата --> Успех | Отмена | Проверка не удалась
Ошибка --Выбрать другой файл--> Picker (новый захват)
Успех --Импортировать ещё--> Picker (новый захват)
Успех/Ошибка/Отмена --Готово/Закрыть--> карта
```

Успех показывается только после того, как файл сохранён и доступен приложению; частичный или
«предварительный» успех не показывается.

## 9. Точные тексты

`{файл}` — отображаемое имя выбранного файла; `{территория}` — имя зафиксированной Territory.

### 9.1. Основная панель

- секция: `GPX`
- строка: `Треки GPX`
- подпись: `Импорт и показ сохранённых треков`

### 9.2. Вложенная страница

- заголовок: `Треки GPX`
- `Импорт GPX` / `Добавить GPX-файл из памяти телефона`
- `Показать трек` / `Выбрать сохранённый трек для карты` / `Скоро`

### 9.3. Импорт

- `Импорт GPX…`
- `{файл}`
- `В территорию «{территория}»`
- фазы: `Читаем файл…` → `Проверяем данные…` → `Сохраняем GPX…`
- при проверке после отмены: `Проверяем результат…`
- действие: `Отмена`

### 9.4. Дубликат

- заголовок: `Этот GPX-файл уже импортирован`
- текст: `Файл с таким же содержимым уже есть в территории «{территория}». Импортировать ещё раз?`
- подтверждение: `Импортировать ещё раз`
- отказ: `Не импортировать`

### 9.5. Успех

- заголовок: `GPX-файл импортирован`
- `{файл}`
- `Сохранён в территории «{территория}».`
- граница: `На карте данные пока не отображаются.`
- действия: `Импортировать ещё` (secondary), `Готово` (primary)

Предупреждение (только если в GPX есть неподдерживаемое содержимое):

- `Некоторые элементы GPX не поддерживаются и не были перенесены. Файл сохранён без изменений.`

Предупреждение не отменяет успех; числа предупреждений не показываются.

### 9.6. Ошибки

| Ситуация | Заголовок | Текст | Primary | Secondary |
|---|---|---|---|---|
| неверный GPX | `Не удалось обработать GPX-файл` | `Файл повреждён или имеет неподдерживаемый формат.` | `Выбрать другой файл` | `Закрыть` |
| превышен лимит | `Файл слишком большой` | `GPX-файл превышает допустимый размер или количество данных.` | `Выбрать другой файл` | `Закрыть` |
| ошибка чтения | `Не удалось прочитать файл` | `Файл недоступен или повреждён. Выберите его снова.` | `Выбрать другой файл` | `Закрыть` |
| нет места | `Недостаточно места` | `Освободите место на телефоне и выберите файл снова.` | `Выбрать файл` | `Закрыть` |
| проверка результата | `Не удалось проверить результат` | `Повторите проверку.` | `Проверить снова` | `Закрыть` |

В каждом ошибочном состоянии показывается `{файл}`. Технические коды, имена исключений, SHA,
номера строк и внутренние категории не показываются.

`Выбрать файл`/`Выбрать другой файл` открывают picker заново с новым захватом; исходный URI не
переиспользуется. `Закрыть` закрывает панель на карту. `Проверить снова` повторяет только
проверку результата и не создаёт новый импорт.

### 9.7. Отмена и отказ от дубля

- отмена до сохранения: `Импорт отменён` / `Файл не был добавлен.` / `Готово`
- отказ от дубля: `Импорт не выполнен` / `Файл уже есть в территории «{территория}». Новый файл не добавлен.` / `Готово`
- изменённый контекст (только если сохранения не было): `Импорт отменён` / `Территория изменилась. Начните импорт снова.` / `Готово`
- отмена системного picker: сообщения нет, возврат на вложенную страницу.

## 10. Терминология

| Было | Должно быть |
|---|---|
| `Импорт трека…` | `Импорт GPX…` |
| `Трек добавлен` | `GPX-файл импортирован` |
| `Трек уже импортирован` | `Этот GPX-файл уже импортирован` |
| `Не удалось прочитать трек` | `Не удалось обработать GPX-файл` |
| `Сохраняем трек…` | `Сохраняем GPX…` |
| `Трек превышает…` | `GPX-файл превышает…` |
| `На карте трек пока не отображается.` | `На карте данные пока не отображаются.` |
| `Новый трек не создан` | `Новый файл не добавлен` |
| `Повторить` (нет места) | `Выбрать файл` |

Не используются: `READY`, `PENDING`, `journal`, `SHA`, `UUID`, `request`, `admission`,
`correlation`, `managed original`, `staging`, `parser`, `profile`, `16 МиБ`, `100000`, `CM1`,
`оригинал объекта`, номера внутренних лимитов.

## 11. Возврат, recreation, повторное открытие

| Событие | Поведение |
|---|---|
| Back/отмена в picker | возврат на вложенную страницу; сообщений нет |
| выбор файла | переход в импорт; прогресс с нуля, без повторного picker |
| поворот/configuration change | состояние панели и импорта сохраняется (ViewModel), прогресс не перезапускается |
| уход в другое приложение | операция продолжается; при возврате — актуальное состояние |
| process death во время picker | импорт не начат; после запуска — обычная карта; можно начать заново |
| process death во время импорта | ложный прогресс и ложный результат не восстанавливаются; незавершённая операция завершается/отменяется существующим recovery; если файл успел сохраниться, он остаётся, а повторный импорт спросит про дубль |
| process death после успеха | данные сохранены; экран результата не восстанавливается; файл появится в будущем списке |
| Back во время импорта | проверка результата (см. §7) |
| Back/свайп после результата | закрыть на карту |

После перезапуска приложения панель не открывается автоматически и не показывает «зависший» импорт.

## 12. fontScale 1.7 и Samsung S25 Ultra

  ~480 dp; учитываются system bars, cutout и gesture navigation.

## 15. Mockup assumptions (обратимые предположения)

1. Раздел GPX расположен после действий `Сбросить фильтры` / `Готово` и разделителя; секция `GPX`, строка `Треки GPX` (уточнение OWNER 2026-10-18).
2. Вложенная страница — внутреннее состояние той же панели; `←` возвращает к основной панели.
3. `Показать трек` виден с бейджем `Скоро` и стрелкой, но в import Slice не открывает пустой
   экран; он станет активным в следующем UI Slice списка/видимости.
4. Импорт — состояние той же панели, без нового экрана/route.
5. Во время импорта свайп и тап по затемнению не закрывают панель; Back/`Отмена` запускают
   проверку результата.
6. Результат остаётся до явного закрытия; auto-dismiss и snackbar не используются.
7. Дубликат проверяется после чтения файла; подтверждение запрашивается до сохранения.
8. Показывается только отображаемое имя файла; размер, SHA, число точек и ID не показываются.
9. Цвета — иллюстрация динамической темы Bee Search; акцент — существующий коричневый toolbar.
10. Кадр picker схематичен и не является pixel-copy системного интерфейса.

## 16. Сценарии приёмки макета

1. **Вход.** Данные на карте: строки исследовательских данных → `Сбросить фильтры` / `Готово` → разделитель → `GPX` / `Треки GPX`. При 1.7 GPX доступен вертикальной прокруткой. `Треки GPX` открывает вложенную страницу; прямого импорта на основной панели нет.
2. **Два действия.** `Импорт GPX` активен; `Показать трек` помечен `Скоро` и не открывает
   пустой экран.
3. **Picker.** Нажатие на GPX-файл завершает выбор и запускает импорт; отмена возвращает на
   вложенную страницу без сообщений.
4. **Обычный импорт.** Прогресс → успех `GPX-файл импортирован` → `Готово`; карта не
   включается.
5. **Дубликат.** Диалог → `Импортировать ещё раз` → успех; `Не импортировать` → `Импорт не выполнен`.
6. **Отмена до сохранения.** `Отмена` → `Проверяем результат…` → `Импорт отменён`.
7. **Отмена после сохранения.** `Отмена`/потеря ответа → `Проверяем результат…` → успех; отмена
   не показывается.
8. **Смена Territory.** Не переносит запрос; завершённый в зафиксированной Territory импорт
   показывает успех для неё; незавершённый — нейтральную отмену.
9. **Ошибки.** Неверный GPX, лимит, чтение, нет места; у «нет места» действие `Выбрать файл`.
10. **fontScale 1.7.** Вложенная страница и результат читаются, кнопки не обрезаются, действия
    перестраиваются.

## 17. Что не решает этот макет

- не активирует `userImportAvailable` и не меняет production UI;
- не проектирует список треков, видимость, карту, Registry, Backup/Restore и Android Auto Backup;
- не меняет Room, parser, Coordinator, managed original store, admission и recovery;
- не является утверждённым UI и не разрешает реализацию до решения OWNER.

Stage1 и H05 остаются OPEN. Единственное предусловие production UI — утверждённый OWNER mockup
PNG+MD; после утверждения потребуется отдельная задача на реализацию UI-слайса.
