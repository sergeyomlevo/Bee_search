# Unified Territory Data Map — текстовая UI specification: отображение research-данных на карте

Статус: APPROVED · 2026-10-02

Утверждённая текстовая UI specification. При approval внесены три owner decisions: состояние «Данные
на карте» сохраняется после перезапуска приложения (§20), состояние принадлежит конкретной Territory
(§20), поведение accordion по умолчанию после появления второго фильтра сознательно отложено (§7).

Implementation **не начата**: этот документ описывает утверждённое поведение, а не реализованный UI, и
не является разрешением менять map modes, Room, schema или migrations.

Входные утверждённые артефакты (approved UI direction V2.1, 2026-10-02):

- `docs/ui/mockups/unified-territory-layers-v2-1.png` — кадры A–D;
- `docs/ui/mockups/unified-territory-layers-v2-1-calendar.png` — кадры E–H;
- `docs/ui/mockups/unified-territory-layers-v2-1.md` — семантический контракт направления.

**PNG — визуальный reference.** Этот документ описывает поведение: что означает каждый control, что
происходит после действия, какие состояния сохраняются, что видно на карте. Он не задаёт pixel
positions, точные цвета, декоративные отступы и размеры элементов.

Документ не проектирует Room, schema, migrations, Compose-структуры, MapLibre-источники и не меняет
D094, I016 и §73.3. Temporal data-model — отдельный этап и здесь не проектируется.

## 1. Термины

| Термин | Значение |
|---|---|
| «Данные на карте» | название функции и заголовок панели; entry point — действие в нижней панели карты |
| тип | research-data type: `Точки наблюдения` (`ObservationPoint`), `Дупла` (`Hollow`), `Колоды` (`LogHive`) |
| видимость типа | включён ли тип на карте; независима от фильтров |
| фильтр типа | filter, принадлежащий конкретному типу; сейчас реально определён один — `Период` |
| «Период» | фильтр типа по календарному интервалу |
| «Всё время» | отсутствие временного ограничения у типа |
| «Источник карты» | отдельная функция выбора подложки; **не часть** «Данные на карте» |

Слово «Слои» как название новой функции не используется.

Доступные сейчас типы — только `Точки наблюдения`, `Дупла`, `Колоды`. `Пасеки` и `Осмотры` —
conceptual/future types: пока соответствующая user-facing capability недоступна, они не показываются
в панели вообще, в том числе недоступными строками (см. «Правило доступности типов в панели» и п. 24
owner decisions в контракте V2.1).

Различие терминологии с существующим экраном: фильтр года в списке точек говорит «Все годы»
(`PointsScreen`), тогда как период отображения на карте говорит «Всё время» (утверждённый макет).
Это разные controls с разным смыслом; формулировка «Всё время» сохраняется как утверждённая.

## 2. Точка входа на карте

Нижняя панель карты (`MapBottomPanel`) следует OWNER-прототипу и D104: четыре равные зоны
слева направо **Анализ → Визуализация → Объекты → Настройки**. Визуализация — это существующая
функция «Данные на карте», без нового route. Отдельная floating/pill кнопка не добавляется.
`Источник карты` остаётся отдельным контролом в прежнем месте.

OWNER visual reference: `C:\App\Bee_search_ui_input\Макет панели инструментов карты MapLibre.png`
(принят как прототип 2026-10-10; не является raster asset приложения).
Панель сохраняет production height **56 dp** независимо от fontScale; увеличение пиктограмм
не отнимает дополнительную высоту карты. Фон — нейтральный тёмно-серый `#555555`, светлые
крупные пиктограммы без видимых подписей: три возрастающих столбика, открытый глаз,
четыре одинаковых квадрата 2×2, шестерёнка с широкими зубьями и читаемым отверстием.
Три тонких приглушённых вертикальных divider имеют отступ от верхнего и нижнего края.
Каждая зона — самостоятельная touch target высотой 56 dp, не меньше 48 dp по ширине;
accessibility сообщает название, role, доступность и состояние.

Анализ пока зарезервирован и disabled: ни destination, ни фиктивного active state нет.
Объекты и Настройки вызывают прежние navigation actions; их экраны заменяют карту, поэтому
панель не сохраняет искусственную выбранную кнопку после возврата. Открытая «Данные на карте»
имеет тёплый коричневый rounded highlight; состояние следует `panelOpen` и снимается при закрытии.
Этот open-state отличается от индикатора активных ограничений, описанного ниже.

Implementation measurements (Samsung, density 3, fontScale 1.7): toolbar 56 dp / 168 px,
each touch zone 90×56 dp. Canvas containers are 48×48 dp (eye 72×48 dp); actual visual heights
are 44 dp / ≈44.7 dp / 44 dp / 46 dp, leaving 6 / ≈5.7 / 6 / 5 dp above and below respectively.
Divider: 1 dp wide, 12 dp vertical insets; rounded toolbar/active shape radius 10 dp, active inset 4 dp,
active color `#966B4F`. Analysis uses reduced icon opacity to communicate unavailable capability.
OWNER color refinement (2026-10-10): the small circular active/restriction indicator uses fresh light
lime-green **`#B7E27A`**, uniformly for any toolbar action reusing that indicator. Its existing 9 dp
size, circular shape and 7 dp top/end positioning are unchanged. This dot is separate from the
warm-brown rounded open-surface highlight; eye, toolbar background, dividers and layout are unchanged.
The existing ModalBottomSheet covers the toolbar when open: active highlight is rendered from real
panelOpen underneath the sheet, not retained after dismissal. Isolated production-component tests
provide device evidence of that highlight without adding a preview route.
Native Compose clickable semantics and Canvas primitives are used without additional dependencies
([official accessibility defaults](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)).

- **DEFAULT STATE.** Действие присутствует всегда; на карте нет global period chip; индикатор
  состояния не горит.
- **ACTIVE-RESTRICTION STATE.** Если ограничения есть, действие получает компактный state indicator.
  Точное условие — в §18.
- Состояние не передаётся только цветом: `contentDescription` действия словесно сообщает, что
  существуют активные ограничения отображения. Конкретная строка не является финальной copy; она
  обязана быть понятной без иконки.

Действие не дублирует basemap: выбор подложки не влияет на состояние research-data display и
наоборот.

## 3. Открытие панели «Данные на карте»

```text
MAP → tap «Данные на карте» → панель (bottom sheet)
```

Контейнер — модальный bottom sheet по утверждённому визуальному reference. Новый navigation
framework не вводится: панель и экран типа живут внутри экрана карты, как существующие map-оверлеи
(выбор покрытия, режим участка).

Панель содержит:

- заголовок «Данные на карте»;
- список доступных research-data types;
- для каждого типа — control видимости, компактную сводку фильтров и affordance перехода в фильтры
  этого типа;
- `Сбросить фильтры` (глобальное действие);
- `Готово` и закрытие.

Future empty sections и недоступные типы не показываются.

## 4. Строка типа

Логический состав строки:

1. control видимости;
2. пользовательское имя типа;
3. компактная сводка фильтров;
4. affordance перехода в фильтры этого типа.

Порядок и взаимное расположение — как на визуальном reference; spacing и layout этим документом не
фиксируются.

**Click target semantics.** Строка содержит два разных действия, и они не смешиваются:

| Действие | Click target | Результат |
|---|---|---|
| переключить видимость | только сам control видимости (48 dp) | меняется **только** видимость; экран фильтров не открывается |
| перейти в фильтры типа | affordance перехода и область строки вне control видимости | открывается экран фильтров этого типа; видимость не меняется |

Тап по control видимости никогда не открывает экран типа; тап по строке вне control видимости не
меняет видимость.

Control видимости — двухсостоятельный (включён/выключен), состояние визуально читается и
объявляется screen reader'ом. В текущем коде приложения `Switch`/`Checkbox` ещё не используются, то
есть control будет новым для этого кода; его поведение и семантика определены здесь, конкретный
Compose-компонент — деталь реализации.

Сводка фильтров — **сводка, а не редактор**: она не раскрывается и не заменяет переход в фильтры
типа. Она всегда показывает текущее значение фильтра, включая случай, когда тип скрыт.

## 5. Видимость

Видимость и фильтры — независимые состояния.

Сценарий из утверждённого направления, дословно по поведению:

```text
Дупла: период = авг–сен 2026, видимость = ВКЛ
→ пользователь выключает видимость
→ маркеры дупел на карте не показываются
→ период остаётся авг–сен 2026 (сводка на строке сохраняется)
→ пользователь включает видимость
→ маркеры дупел возвращаются
→ снова применяется авг–сен 2026
```

Выключение видимости **не означает**:

- сброс фильтра;
- удаление записи;
- изменение объекта;
- изменение research data.

То же правило для включения: включение видимости не сбрасывает и не задаёт фильтры типа.

Отдельного действия «показать все скрытые типы» не вводится: включить тип — один тап по его control
видимости.

## 6. Экран фильтров типа

```text
«Данные на карте» → строка типа → экран фильтров типа
```

- Заголовок — пользовательское имя типа («Точки наблюдения», «Дупла», «Колоды»).
- `Назад` возвращает в «Данные на карте» и **не теряет** изменения: изменений в смысле «черновик» не
  существует (см. §14).
- Отдельный «экран календаря» как обязательный уровень не создаётся. Экран типа — **список
  type-specific filters**; в нём `Период` и применимые structured numeric filters (см. owner correction ниже).
- Header следует существующей компактной конвенции приложения (`CompactScreenHeader`: одна строка,
  back-control 48 dp с описанием «Назад»), а не `TopAppBar`.

## 7. Строка фильтра (accordion)

Каждый type-specific filter — accordion-секция.

**COLLAPSED:** имя фильтра · текущее значение · affordance раскрытия.
**EXPANDED:** та же строка · affordance сворачивания · ниже — редактор этого фильтра.

| Элемент | Требование |
|---|---|
| имя фильтра | «Период» |
| текущее значение | сводка (см. §8), видна и в свёрнутом, и в раскрытом состоянии |
| affordance | стандартная Material-конвенция expand/collapse: вертикальный шеврон, разворачивающийся при раскрытии; нестандартные направления стрелок не вводятся |
| accessibility | состояние объявляется: раскрыто / свёрнуто |
| touch target | ≥ 48 dp на строку и на affordance |

Проектная конвенция для accordion уже существует в приложении (`HelpScreen`): заголовок — кнопка с
`stateDescription` «Развёрнуто» / «Свёрнуто», а декоративный указатель исключён из семантики, чтобы
доступным именем оставалось имя секции. Этот же приём применяется здесь.

**Расширяемость.** Позже рядом могут появиться другие type-specific filters как sibling accordion
sections. Их имена и значения сейчас не придумываются, placeholders не рисуются и не объявляются.

**Одновременно раскрыт максимум один фильтр:** раскрытие другого сворачивает предыдущий. Отличие от
существующего `HelpScreen` (там секции раскрываются независимо) сделано осознанно, ради меньшей
прокрутки и меньшего визуального шума в поле. Это **UI behaviour экрана, а не domain invariant**:
он не влияет на значения фильтров и на данные.

Пока `Период` — единственный определённый фильтр, при входе на экран типа он **раскрыт по
умолчанию**.

Поведение по умолчанию после появления второго фильтра эта specification **не определяет**: оно будет
решено вместе с реальным новым фильтром, исходя из фактического набора фильтров и UX. Общее правило
«`Период` всегда раскрыт по умолчанию» сейчас не принимается. Это сознательно отложенное future UI
decision, а не незакрытый вопрос текущей specification.

## 8. Период: сводка

Сводка всегда описывает **интервал** и использует **самую грубую точность, которая выражает этот
интервал точно**:

| Интервал | Сводка |
|---|---|
| ограничения нет | `Всё время` |
| ровно один календарный год | `2026` |
| ровно несколько полных лет подряд | `2024–2026` |
| ровно один полный календарный месяц | `авг 2026` |
| ровно несколько полных месяцев подряд | `авг–сен 2026` |
| ровно один день | `17.08.2026` |
| всё остальное | `10.08.2026 — 01.09.2026` |

Правило не зависит от текущей точности редактора: один и тот же интервал даёт одну и ту же сводку.

Каждый тип хранит **собственное** UI-состояние фильтра. Global period не вводится: периода «для всей
карты» не существует.

## 9. Период: точность и общее правило выбора

Раскрытый `Период` содержит control точности `Год | Месяц | День`. Точность выбирается явно.

Общее правило на всех трёх уровнях — одно и то же:

> **одна единица времени ИЛИ один непрерывный диапазон.**

Mental model для `Год`, `Месяц` и `День` не различается.

Взаимодействие выбора (одинаково для года, месяца и дня):

| Ситуация | Tap | Результат |
|---|---|---|
| выбора нет | по единице | выбрана эта единица (начало = конец) |
| выбрана одна единица | по другой единице | диапазон между ними, границы нормализуются (порядок тапов не важен) |
| выбрана одна единица | по той же единице | выбор снимается → `Всё время` |
| выбран диапазон | по любой единице | начинается новый выбор с этой единицы |

Правила, следующие из таблицы:

- диапазон всегда непрерывен; **disjoint-выбор невозможен by construction** — multi-select не
  вводится, «май + сентябрь без июня–августа» и «2024 + 2026 без 2025» этим UI не выражаются;
- диапазон можно сократить: тап по нужной границе начинает новый выбор, затем второй тап задаёт
  вторую границу;
- изменение выбора никогда не показывает error/destructive state.

Навигация внутри редактора (переход между годами на уровне «Месяц», между месяцами на уровне «День»):

- навигация **не является** действием выбора и никогда не меняет и не сбрасывает выбор;
- сетка показывает только единицы отображаемого года/месяца; частью выбора, лежащая вне отображаемого
  периода, в сетке не видна, но остаётся в силе и всегда отражена в сводке;
- доступные для навигации годы — годы, в которых есть записи этого типа в текущей Territory
  (утверждённое допущение макета). На уровне «День» навигация по месяцам идёт шагом месяц в пределах
  того же окна лет (от самого раннего до самого нового года с записями), с переходом через границу
  года; в начале и в конце окна соответствующая стрелка недоступна.

## 10. Уровень «Год»

Выбирается один год или непрерывный диапазон лет. Показывается список годов, в которых есть записи
этого типа.

Семантика значения (поведенческая, не storage):

```text
2026      → 01.01.2026 — 31.12.2026
2024–2026 → 01.01.2024 — 31.12.2026
```

Визуально различаются: выбранная одна единица, границы диапазона и единицы внутри диапазона. Различие
не передаётся только цветом (см. §21). Storage representation этим документом не проектируется.

Список годов пуст (у типа нет записей) — редактор не показывает пустой список без объяснения: вместо
него одна короткая поясняющая строка; пояснение обосновано тем, что список строится из данных, и без
него пустой экран неотличим от неработающего.

## 11. Уровень «Месяц»

Выбирается один месяц или непрерывный диапазон месяцев. Показывается сетка 12 месяцев отображаемого
года; отображаемый год переключается навигацией и не является частью значения фильтра.

```text
август 2026          → 01.08.2026 — 31.08.2026
август–сентябрь 2026 → 01.08.2026 — 30.09.2026
```

Один месяц означает период от первого до последнего календарного дня этого месяца.

Диапазон может пересекать границу года: `декабрь 2025 – февраль 2026` моделью не запрещается и
собирается навигацией между годами (см. §9). Промежуточные месяцы диапазона показаны как входящие в
диапазон.

Начальный отображаемый год: год начала текущего выбора; если выбора нет — самый новый год с записями
этого типа; если записей нет — текущий календарный год (в этом случае список годов пуст и действует
правило §10).

## 12. Уровень «День»

Выбирается одна дата или точный непрерывный диапазон дат. Первый выбор — начало, второй — конец;
если второй выбранный день раньше первого, диапазон нормализуется в `[раньше, позже]` без error и
destructive state.

Диапазон может пересекать границу месяца и года: `10.08.2026 — 01.09.2026` собирается как «`10` в
августе → переход к сентябрю → `1`».

Начальный отображаемый месяц: месяц начала текущего выбора; если выбора нет — самый новый месяц, в
котором есть записи этого типа; если записей нет — текущий календарный месяц.

## 13. Переключение точности

Точность — это **режим редактирования и отображения**, а не значение фильтра.

Правило:

> Переключение точности **никогда не меняет и не сбрасывает** фильтр. Меняется только то, как интервал
> показывается и редактируется.

Редактор проецирует текущий интервал на выбранную точность:

- если интервал выражается на этой точности точно — проекция показывается как текущий выбор;
- если не выражается — редактор показывает **отсутствие выбора**, а сводка продолжает показывать
  реальное значение; первый тап в редакторе начинает новый выбор.

Разбор требуемых случаев:

| Переход | Текущее значение | Что показывает редактор | Значение фильтра |
|---|---|---|---|
| `Год` → `Месяц` | `2026` | `янв–дек 2026` выбранными (интервал выражается точно) | не меняется |
| `Месяц` → `День` | `авг–сен 2026` | `01.08.2026 — 30.09.2026` выбранным | не меняется |
| `День` → `Месяц` | `10.08.2026 — 01.09.2026` | выбора нет (интервал не выражается целыми месяцами) | не меняется: `10.08.2026 — 01.09.2026` |
| `Месяц` → `Год` | `авг–сен 2026` | выбора нет (интервал не выражается целыми годами) | не меняется |
| любой → любой | `Всё время` | выбора нет | `Всё время` |

Почему так: интервал никогда не расширяется и не теряется молча. Расширяющая проекция (например
`10.08–01.09.2026` → `авг–сен 2026`) молча меняла бы то, что видит пользователь, а сброс фильтра при
невыразимом интервале молча снимал бы ограничение. Оба варианта отклонены.

Точность, показываемая при входе на экран типа, — **самая грубая точность, которая выражает текущий
интервал точно** (то же правило, что и у сводки). Если периода нет — `Год`.

Переключение точности не требует отдельного подтверждения и не является destructive действием.

## 14. Применение изменений

Черновиков (draft) нет. Любое изменение выбора — видимость, год, месяц, день, сброс — **применяется
немедленно**.

- Изменение сразу влияет на состояние карты; при открытой панели карта частично видна сверху, при
  открытом экране типа — полосой сверху.
- Немедленная обратная связь в первую очередь — обновлённая сводка на строке фильтра и строка типа в
  панели, которые меняются сразу.
- `Готово` только закрывает панель и возвращает полевой экран; оно не «сохраняет» и не «отменяет».
  Это относится к `Готово` **в панели**; `Готово` на экране типа завершает настройку этого типа и
  возвращает к списку типов, не закрывая панель (owner clarification, 2026-10-10: панель — это одна
  сессия настройки, и ни одно изменение внутри неё не должно её закрывать).
- `Назад` с экрана типа возвращает в панель и не отменяет изменения.
- Закрытие панели не сбрасывает фильтры и не меняет видимость.
- Несохранённых изменений, которые можно потерять, не существует; предупреждений о несохранённых
  изменениях для этого UI не требуется.

Это соответствует утверждённому контракту V2.1 и существующим конвенциям приложения: выбор года на
экране точек, режим просмотра и настройки применяются немедленно. Draft-модель существует только в
редакторе геометрии участков, где изменение разрушительно и требует подтверждения; к фильтрам
отображения она не переносится.

## 15. Сброс

**`Сбросить период`** (внутри раскрытой секции `Период`):

- действует только на `Период` **текущего** типа;
- результат — `Всё время`;
- не меняет видимость этого типа;
- не меняет другие фильтры типа (когда они появятся);
- не меняет фильтры других типов;
- не удаляет research data;
- подтверждение не запрашивается; действие не destructive;
- секция **остаётся раскрытой**: кнопка находится внутри раскрытой секции, и сворачивание скрыло бы
  результат действия.

**`Сбросить фильтры`** (в панели «Данные на карте»):

- снимает фильтры у **всех доступных** типов → `Всё время`;
- **не меняет** видимость ни одного типа;
- не удаляет research data; подтверждение не запрашивается;
- присутствует всегда; если ни у одного типа нет активного фильтра, нажатие ничего не меняет и не
  показывает ошибку.

Пример:

```text
до:      Точки наблюдения = 2026, ВКЛ
         Дупла            = авг–сен 2026, ВЫКЛ
после:   Точки наблюдения = Всё время, ВКЛ
         Дупла            = Всё время, ВЫКЛ
```

## 16. Навигация и закрытие

```text
MAP → «Данные на карте» → TYPE FILTERS → «Данные на карте» → MAP
```

| Действие | Результат |
|---|---|
| tap «Данные на карте» | открывается панель |
| tap строки типа (вне control видимости) | открывается экран фильтров этого типа |
| `Назад` на экране типа | возврат в «Данные на карте»; изменения сохраняются |
| `Готово` | закрывает панель и возвращает карту; на экране типа `Готово` завершает настройку этого типа и возвращает к списку типов (§14) |
| close `✕` в панели | закрывает панель; состояние сохраняется |
| системный Back | `Назад` на экране типа, если он открыт; иначе закрывает панель; на карте — обычное поведение карты |
| tap вне панели (если конвенция bottom sheet это допускает) | закрывает панель; состояние сохраняется |
| свайп панели вниз | закрывает панель; состояние сохраняется |

Back никогда не сбрасывает фильтры и не меняет видимость. Приоритет системного Back согласуется с
существующей конвенцией карты (`BackHandler` активен только для открытого оверлея), чтобы Back не
перехватывался, когда ни панель, ни экран типа не открыты.

## 17. Результат на карте

На карте отображаются только записи, которые одновременно:

1. принадлежат типу с видимостью «включён»;
2. удовлетворяют активным фильтрам этого типа.

Если у типа нет активных фильтров — показываются все доступные записи этого типа в текущем контексте
Territory, согласно остальным существующим правилам проекта.

Фильтр применяется к canonical research date типа (D094): точки наблюдения — по дате наблюдения,
дупла и колоды — по дате фиксации. `created_at` не подменяет research date. Для будущих типов —
соответствующая canonical research date из D094.

Пользовательская формулировка внутри интерфейса (короткая, без понятий существования):
«Точки фильтруются по дате наблюдения.», «Дупла фильтруются по дате фиксации.»,
«Колоды фильтруются по дате фиксации.»

Этот документ не определяет SQL, Flow, repository API, MapLibre sources и Compose state.

## 18. Состояние индикатора

```text
indicator = ON
⟺ существует хотя бы один ДОСТУПНЫЙ тип, у которого
    видимость ВЫКЛ
    ИЛИ
    есть активный фильтр (для текущего набора: период ≠ «Всё время»)
```

- Значение по умолчанию: у всех доступных типов видимость включена и период `Всё время` — индикатора
  нет. Это следует из утверждённого default-состояния V2.1.
- Типы, недоступные пользователю, в условие не входят: у них нет ни строки, ни состояния.
- Выбор подложки (`Источник карты`) в условие **не входит**: это отдельная система.
- Индикатор не заменяет собой словесное описание в `contentDescription` и не является единственным
  носителем состояния.

## 19. Пустые состояния и состояние на карте

Диалогов и оверлеев на карте не вводится. Поведение:

| Случай | Поведение |
|---|---|
| A. Тип виден, но после фильтрации совпадений нет | карта просто не показывает маркеры этого типа; период остаётся активным и виден в сводке и на строке типа |
| B. Тип виден, но в Territory нет записей этого типа | то же: маркеров нет; состояние фильтра не меняется |
| C. Все типы скрыты | на карте нет research-маркеров; индикатор горит; панель остаётся способом понять причину |
| D. Фильтры активны и результат пуст | то же, что A: пустая карта не является ошибкой |

Объясняющих баннеров на карте нет: они закрывали бы полевую карту и требовали бы дополнительного
жеста, тогда как причина пустого результата всегда видна в «Данные на карте» в один тап. Исключение —
пустой список годов в редакторе (`§10`), где пояснение нужно, чтобы пустой список был отличим от
неработающего контрола.

## 20. Territory и persistence

**Состояние принадлежит Territory.** Состояние «Данные на карте» — видимость доступных типов и
значения их фильтров — принадлежит конкретной Territory. У каждой Territory собственное состояние;
состояния разных Territory не смешиваются и не влияют друг на друга.

```text
Territory A: Точки = 2026, Дупла = авг–сен 2026, Колоды = ВЫКЛ
→ пользователь переключается на Territory B
→ применяется собственное состояние Territory B, а не настройки Territory A
→ пользователь возвращается в Territory A
→ восстанавливается ранее сохранённое состояние Territory A
```

Состояние — **per-Territory + persistent**. Смена Territory не является сбросом: это переход к
состоянию другой Territory; возврат восстанавливает состояние первой.

**Territory без сохранённого состояния** (новая Territory, в которой состояние ещё никогда не
задавалось) использует default state согласно этой specification: все доступные типы видимы, у всех
период `Всё время`.

**Persistence после process death / перезапуска приложения.** Состояние сохраняется и восстанавливается
без ручной повторной настройки: обычное закрытие или перезапуск приложения не должны требовать
заново задавать видимость типов и периоды.

**Persistence в пределах работы приложения:**

- переключение видимости не сбрасывает фильтры;
- переход `тип → панель → тип` сохраняет состояние;
- закрытие и повторное открытие панели не сбрасывает фильтры и не меняет видимость;
- переключение подложки не сбрасывает и не меняет состояние отображения research-данных;
- смена Territory переключает на состояние соответствующей Territory (см. выше);
- никакое из этих действий не изменяет и не удаляет research data.

**Что здесь намеренно не определяется:** конкретный persistence mechanism, место и формат хранения,
storage representation, ключи, serialization, repository implementation и migration. Это
implementation/design detail соответствующего следующего этапа, а не решение этой specification.

## 21. Доступность

Обязательные требования:

- touch targets ≥ 48 dp: действие в нижней панели, control видимости, строка типа и её affordance,
  строка фильтра и её affordance, единицы календаря, обе нижние кнопки;
- системный `fontScale` 1.7: панель и экран типа прокручиваются; строка фильтра не имеет
  фиксированной высоты — при увеличенном шрифте значение переносится на вторую строку и не
  сталкивается с именем фильтра; сетка месяцев при увеличенном шрифте перестраивается в меньшее число
  колонок; заголовок экрана типа остаётся в одну строку с ellipsis (существующая конвенция compact
  header);
- screen reader: каждое icon-only действие имеет `contentDescription` без опоры на иконку;
- состояние control видимости объявляется словами (включено/выключено), а не только цветом;
- текущее значение фильтра объявляется словами: имя фильтра + значение (конвенция существующего
  фильтра года: «Год: 2026»), включая `Всё время`;
- состояние accordion объявляется (раскрыто/свёрнуто), декоративный указатель исключён из семантики;
- выбранный диапазон календаря различим не только цветом: выбранная единица, границы диапазона и
  единицы внутри диапазона имеют различающееся состояние, и выбранный интервал всегда читается в
  сводке;
- индикатор активных ограничений продублирован словами в `contentDescription`;
- отсутствуют обязательные long-press, hover и drag-жесты;
- порядок фокуса — сверху вниз по содержимому панели и экрана типа.

Конкретные цвета не задаются: используются существующие токены темы.

## 22. Полевое использование

- телефон, работа одной рукой: основные действия доступны обычным tap; ни одно обязательное действие
  не требует точного drag;
- отсутствие обязательного точного drag критично для календаря: выбор диапазона выполняется тапами;
- крупные цели и минимум мелких элементов: поиск даты не требует попадания в мелкую цель;
- солнце: состояние читается по тексту и форме, не только по оттенку;
- быстрые операции: типовой сценарий (скрыть тип, задать год, снять ограничение) укладывается в
  несколько tap;
- вторичных модальных подтверждений для non-destructive действий нет.

## 25. Acceptance scenarios

1. **Default.** Все доступные типы (Точки наблюдения, Дупла, Колоды) видимы, ни у одного нет
   ограничения периода; индикатор на действии не горит.
2. **Точки наблюдения = 2026.** Точки вне 2026 на карте не показываются; видимость и периоды других
   типов не меняются; сводка строки — `2026`.
3. **Точки наблюдения = 2024–2026.** Непрерывный диапазон лет; сводка — `2024–2026`; смысл —
   01.01.2024 — 31.12.2026.
4. **Дупла = авг–сен 2026.** Сводка — `авг–сен 2026`; смысл — 01.08.2026 — 30.09.2026; дупла вне
   периода не показываются.
5. **Смешанные периоды.** `Точки наблюдения = 2026`, `Дупла = авг–сен 2026`, `Колоды = Всё время`
   одновременно; периоды не влияют друг на друга; индикатор ON.
6. **Скрытие с сохранением фильтра.** Дупла с периодом `авг–сен 2026` выключаются, затем включаются:
   период остаётся ровно `авг–сен 2026`, повторный выбор не требуется.
7. **Global reset.** До: Точки `2026` ВКЛ, Дупла `авг–сен 2026` ВЫКЛ. После `Сбросить фильтры`: Точки
   `Всё время` ВКЛ, Дупла `Всё время` ВЫКЛ; видимость не изменилась; данные не удалены.
8. **Точный диапазон.** `10.08.2026 — 01.09.2026`: собирается через уровень «День» с переходом через
   границу месяца; сводка показывает обе даты.
9. **Пустой результат.** После фильтрации у типа нет совпадений: маркеров этого типа на карте нет,
   период остаётся активным и видимым в сводке и на строке типа; диалогов не появляется.
10. **Переключение подложки.** При активных фильтрах смена `Источник карты` не меняет ни видимость, ни
    периоды, ни индикатор.
11. **Переключение точности без потери фильтра.** `авг–сен 2026` → точность «День» показывает
    01.08.2026 — 30.09.2026 и не меняет значение; `10.08.2026 — 01.09.2026` → точность «Месяц»
    показывает отсутствие выбора и сохраняет исходный интервал в сводке.
12. **Сохранение после перезапуска.** Territory A: `Точки = 2026`, `Дупла = авг–сен 2026`,
    `Колоды` выключены. Приложение закрыто, процесс пересоздан, пользователь возвращается в
    Territory A: состояние прежнее — `Точки = 2026`, `Дупла = авг–сен 2026`, `Колоды` выключены;
    повторная ручная настройка не требуется.
13. **Изоляция Territory.** Territory A имеет состояние A, Territory B — состояние B. Переход A → B
    показывает состояние B; возврат B → A восстанавливает состояние A. Territory C, которая ещё
    никогда не имела сохранённого состояния, открывается с default state (все доступные типы видимы,
    период `Всё время`).

## 26. Что specification намеренно не определяет

Точные цвета, размеры, отступы и позиции; конкретный Compose-компонент для visibility control,
accordion, календаря и контейнера панели; Room schema, migrations, поля дат фиксации; конкретный
persistence mechanism и storage representation сохраняемого display state; repository API, Flow и SQL;
MapLibre sources и композиция оверлеев; §73.3; map modes и судьбу `ONLINE`/`VECTOR`/`SENTINEL`; состав
будущих type-specific filters; тексты Help; pixel-perfect соответствие PNG.

Поведение после process death / перезапуска этим документом **определено** (§20) и в этот список не
входит.

## 27. Отложенные решения

Незакрытых blocking-вопросов specification не содержит: утверждённое направление V2.1 и три решения
approval зафиксированы в разделах выше, а остальные детали разрешены существующими конвенциями
проекта. Что следует из утверждённого направления — весь документ; здесь оно не дублируется.

**Разрешено через существующие конвенции проекта** (не является вопросом к владельцу): немедленное
применение без draft (выбор года, режим просмотра и настройки в приложении применяются сразу; draft
существует только в редакторе геометрии); accordion-семантика «Развёрнуто»/«Свёрнуто» и исключение
декоративного указателя из семантики (`HelpScreen`); компактный заголовок вместо `TopAppBar`
(`CompactScreenHeader`); back через `BackHandler`, активный только для открытого оверлея (`BeeMap`);
именование контроля значением в `contentDescription` (`"Год: …"`, `"Источник карты: …"`); список
годов из данных (`PointsViewModel`).

**Отложено сознательно:**

1. **Persistence mechanism.** Место, формат, ключи, serialization, repository implementation и
   migration для сохранения состояния — implementation/design detail следующего соответствующего
   этапа. Поведение (per-Territory + persistent, §20) при этом уже определено и здесь не
   переоткрывается.
2. **Default accordion state при появлении второго фильтра.** Решается вместе с реальным новым
   фильтром, исходя из фактического набора фильтров и UX (§7). Общее правило «`Период` всегда раскрыт
   по умолчанию» сейчас не принимается.

Решения, уже принятые владельцем — направление V2.1 и три решения approval (persistence после
перезапуска, per-Territory состояние, отложенное поведение второго фильтра) — здесь не переоткрываются.


## Owner correction — final I6 FilterSet (2026-10-10)

Существующая основная карта — unified research-data map. `Точки наблюдения` остаётся
таблицей / браузером records с прежними list filters и разрешённым редактированием;
собственного map mode и переключателя больше нет. Новая route «Визуализация» не создаётся.
Временный `DEV: маркеры` и его preview удалены; остальные diagnostics не затронуты.
Production D102 pictograms, normal 32 dp и selected type pictogram + halo сохраняются.

Owner extension 2026-10-10: marker → selected halo + compact preview → явное «Открыть запись» →
существующая полная запись ObservationPoint/Hollow/LogHive по реальному UUID. Preview содержит
идентификацию объекта, не копию полной записи. Back возвращает к той же Territory, camera/zoom,
visibility/FilterSet и доступному выбранному объекту. Закрытие preview очищает только selection.
Preview строится только из текущих видимых filtered markers; excluded object не имеет preview.
Overlap сохраняет обычный порядок hit testing; увеличение карты разделяет близкие markers,
clustering/spiderfy/auto-spacing не вводятся. Preview скрыт в режимах placement/участки editing.

Каждый тип хранит `visible + FilterSet`, независимо от других типов и Territory.
ObservationPoint: период, количество Bee records этого ObservationPoint, суммарное количество
всех FlightCycle records всех его Bee (включая открытые). Hollow / LogHive: период,
высота летка (см), наружный диаметр (см). Это существующие structured measurements.
Числовые bounds включительны; пустое поле — открытая граница, оба пустые — без ограничения,
равные bounds — точное значение, zero — реальное значение. Min > max, отрицательное или
непредставимое число не применяется; показана ошибка, последний валидный фильтр сохраняется.
Используются компактные поля `От` / `До`, без slider и искусственного максимума.

Экран типа — accordion: не более одной раскрытой секции. `Готово` и Back из типа возвращают
к списку типов. Видимость и любые фильтры применяются immediately и не закрывают sheet/editor.
Закрытие списка: `Готово`, `✕`, Back, swipe/scrim по ModalBottomSheet semantics.
`Сбросить фильтры` снимает все критерии всех типов, сохраняя visibility и session.
`Сбросить период` снимает только период; локальный `Сбросить` снимает только свой numeric criterion.

Без критериев summary — `Все данные`; только период — его summary; несколько критериев —
например `2026 · пчёл ≥ 5 · циклов ≥ 10`. При fontScale 1.7 summary переносится под название.

Одна календарная единица либо непрерывный диапазон на всех уровнях:
DAY 10.05 → 15.05.2026 = [2026-05-10, 2026-05-15]; одиночный день = [day, day].
MONTH май → июль 2026 = [2026-05-01, 2026-07-31]; март → сентябрь сохраняет все месяцы между ними.
YEAR 2024 → 2026 = [2024-01-01, 2026-12-31]. Cross-year month selection разрешён:
декабрь 2025 → февраль 2026 = [2025-12-01, 2026-02-28]. Второй тап задаёт конец,
не заменяет первый; после завершённого диапазона следующий тап начинает новый выбор.

Canonical research dates не меняются. Bounded physical period исключает NULL fixation_date,
unbounded сохраняет NULL; активный measurement filter исключает unknown measurement.
FilterSet сохраняет SQL semantics; D103 отдельно добавляет physical fixation moments в Room v14. Все predicates выполняются в SQL до materialization;
период и counts пересекаются в одном aggregate query, независимые optional bounds не требуют
combinatorial DAO methods. Per-Territory DataStore codec v2 читает v1, добавляя открытые
numeric bounds; default state не создаёт отдельную persistent запись.
